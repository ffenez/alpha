# alpha

Alpha — самостоятельное Android-приложение для дозиметров-спектрометров серии RadiaCode (101/102/103/103G/110, Zero): подключение по BLE, живые показания, спектр, журнал. Не «клиент RadiaCode», а свой прибор наблюдения с упором на приватность и качество UI; имя прибора остаётся именем прибора (протокол, модели, форматы файлов), именем приложения оно не является.

## Stack

- Kotlin, Jetpack Compose (Material 3), coroutines/Flow; minSdk 26
- BLE: Kable (Apache-2.0) + собственный порт протокола cdump/radiacode (MIT, атрибуция обязательна)
- Хранение: Room (SQLite)
- Карта: osmdroid (растровые тайлы OpenStreetMap); геолокация — LocationManager (не Fused)

## Invariants

- Данные измерений и координаты не покидают устройство. Никакой телеметрии, аналитики, крэш-репортинга в сеть. Единственный разрешённый сетевой трафик — анонимная загрузка тайлов карты (с агрессивным кэшем; тайл-запросы не должны содержать ничего, кроме координат тайла).
- Никаких зависимостей от Google Play Services / Firebase — целевое устройство GrapheneOS без GMS.
- BLE-протокол RadiaCode реверс-инжинирен сообществом; собственный код протокола писать по документации/идеям, код копировать только из совместимых по лицензии источников с атрибуцией (GPL-код не копировать).
- Дозиметрические величины: хранить сырые значения и единицы (мкЗв/ч, cps), не терять точность при конвертации.
- **Приложение работает со всей серией, а не с одной моделью.** Кристалл, разрешение, шкала и чувствительность разные: числа берутся из `DeviceModel` по серийному номеру, а неопознанный прибор получает консервативный профиль и честную строку на экране. Константу конкретной модели внутри алгоритма писать нельзя — только правило от параметров прибора.

## Commands

- Сборка: `JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:assembleRelease` — **отдаётся только release**. Релизная сборка выходит неподписанной, поэтому её выравнивают и подписывают отладочным ключом (своего релизного ключа у проекта нет):

  ```
  BT=/home/dev/Android/sdk/build-tools/35.0.0
  $BT/zipalign -f -p 4 app/build/outputs/apk/release/app-release-unsigned.apk /tmp/aligned.apk
  JAVA_HOME=/home/dev/.local/jdk PATH=/home/dev/.local/jdk/bin:$PATH \
    $BT/apksigner sign --ks ~/.android/debug.keystore --ks-pass pass:android \
    --ks-key-alias androiddebugkey --out apk/app-release.apk /tmp/aligned.apk
  ```

  Debug-сборку (`:app:assembleDebug`, копируется в `apk/app-debug.apk`) собирают только под отладчик или логи и в `apk/` не оставляют.
- Тесты: `JAVA_HOME=/home/dev/.local/jdk ./gradlew test` (JVM-тесты :protocol и :app)
- Lint: `JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:lintDebug`

## Правила, которые нельзя нарушать

Полный список решений с причинами — `docs/decisions/key-decisions.md`.
Сжатое устройство движка — `docs/architecture/engine-and-algorithms.md`.
Ниже — то, что действует всегда и проверяется тестами.

### Вывод

- Слова **«норма», «безопасно», «опасно», «допустимо»** (и `safe/normal/dangerous/harmless`)
  не появляются ни в одной формулировке. Приложение описывает наблюдение и
  называет критерий, а не выносит приговор.
- **«Обнаружен» не пишется никогда.** Совпадение энергии — гипотеза; вердикты о
  кандидатах даёт только движок доказательств (ADR 006).
- **Непринятие различия ≠ равенство.** Критерий проверял отличие и не нашёл его —
  так и говорится; «совпадает», «идентично», «стабильно» запрещены.
- Любое отношение называет **знаменатель** («×4,8 к P90 профиля»), любой разброс —
  свою меру (`SD`/`MAD`/`IQR`) с единицей.
- Если картинка может изменить физический смысл данных, ограничение стоит **на
  картинке**, а не только в справке.

### Данные

- Измерения и координаты **не покидают устройство**. Единственный сетевой трафик —
  тайлы карты. Ни телеметрии, ни аналитики, ни крэш-репортинга в сеть.
- Никаких Google Play Services и Firebase.
- Сырые значения и единицы прибора хранятся как есть; конвертация — только на выводе.
- Данные исчезают **только** по явной команде человека (уборка журнала и срез
  хранения, выключенный по умолчанию).

### Как здесь пишут код

- Тестируемая логика — чистый JVM (`analysis/`, `baseline/`, `ui/logic/`); экраны тонкие.
- Тексты — в Kotlin-каталогах `ui/text/` по областям, а не в `strings.xml`.
- Инженерный параметр называется инженерным и объясняется числом, а не подбирается молча.
- Новая технология — только с проверяемым преимуществом; идея из чужого проекта
  реализуется своим кодом (лицензии проверяются).
- **Пользовательское изменение попадает в «О приложении»**: выжимка в одну-две
  фразы в `ui/text/ReleaseStrings` и номер версии в `app/build.gradle.kts` —
  вместе, их совпадение держит тест. Список ведётся руками, из git он не
  выводится: коммит объясняет причину правки, а запись — что человек увидит на
  экране. Перечень пунктов вместо выжимки — отчёт о работе, а не обновление.

### Проверки перед «готово»

```
JAVA_HOME=/home/dev/.local/jdk ./gradlew test
JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:smokeTest
JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:lintDebug
JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:assembleRelease
```

Упавший тест на формулировку — сначала повод подумать, не сломано ли утверждение,
и только потом править тест.
