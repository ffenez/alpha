# radiacode

Современное Android-приложение для дозиметра-спектрометра RadiaCode 110: подключение по BLE, живые показания, спектр, журнал. Замена официального приложения с упором на приватность и качество UI.

## Stack

- Kotlin, Jetpack Compose (Material 3), coroutines/Flow; minSdk 26
- BLE: Kable (Apache-2.0) + собственный порт протокола cdump/radiacode (MIT, атрибуция обязательна)
- Хранение: Room (SQLite)
- Карта: osmdroid (растровые тайлы OpenStreetMap); геолокация — LocationManager (не Fused)

## Invariants

- Данные измерений и координаты не покидают устройство. Никакой телеметрии, аналитики, крэш-репортинга в сеть. Единственный разрешённый сетевой трафик — анонимная загрузка тайлов карты (с агрессивным кэшем; тайл-запросы не должны содержать ничего, кроме координат тайла).
- Никаких зависимостей от Google Play Services / Firebase — целевое устройство GrapheneOS без GMS.
- BLE-протокол RadiaCode реверс-инжинирен сообществом; собственный код протокола писать по документации/идеям, код копировать только из совместимых по лицензии источников с атрибуцией (GPL-код не копировать).
- Дозиметрические величины: хранить сырые значения и единицы (мкЗв/ч, cps), не терять точность при конвертации.

## Key decisions

- Протокол — чистый Kotlin-порт cdump/radiacode; Open-RadiaCode-Android без лицензии — только идеи, не код (ADR 001)
- Один запрос в полёте, матчинг по эхо заголовка; канонический SPEC_ACCUM = 0x205. Пропуск seq в DATA_BUF не рвёт разбор (записи самоограничены — ресинк, счётчик `seqGaps` в `DataBufResult`, идея qtradiacode); несовпадение эха = хвост прежнего обмена → слить ожидающие ответы и ровно один повтор со свежим seq после 100 мс
- Устройство держит одного BLE-клиента: сосуществование с официальным приложением невозможно, это ограничение UX
- Непрерывное измерение — foreground service + запрос исключения из battery optimization
- UI — дизайн-система «Научный терминал» (вариант F, docs/design/design-language.md): IBM Plex Sans/Mono (OFL, бандлятся), тёмная тема основная + светлая по системе, карточки 14dp/рамка 1dp, каждая величина с погрешностью, оси графиков всегда подписаны; токены в `app/.../ui/theme`, компоненты в `app/.../ui/components`; экраны тонкие, вся тестируемая логика UI — в `ui/logic` (чистый JVM)
- Baseline — взвешенная перцентильная полоса P10–P90 по минутным корзинам ПРОФИЛЯ (окно 14 дней, отсечка >3×медианы, активация после 3 ч); отклонение = величина И длительность (`PersistenceTracker`); движок чистый JVM в `app/.../baseline/` (ADR 002). Статистики расширены до P25/P75 + взвешенный MAD = median(|xᵢ − медиана|) БЕЗ коэффициента 1.4826 (он предполагает нормальность, спец §4.1 её запрещает допускать), плюс длительность, число сырых выборок и число корзин (честное n порядковых статистик); `BaselineConfig.ALGORITHM_VERSION`
- **Профили вместо «мест»** (спец §3): `profiles` = имя, иконка, вложенность на ОДИН уровень («Дом / Спальня»; глубже — неоднозначность, чьи это статистики), архив, `autoActivate`, `baselineLearning`, `role` (user/transit/no_place). Правила дерева — чистый `ui/logic/ProfileTree` (нельзя вложить родителя, нельзя заархивировать последний живой профиль, архив родителя забирает детей). Пресеты: Дом, Офис, Дача, Родители, В пути, Без места; последние два по смыслу «ситуация, а не комната» — обучение фона у них выключено
- **Авто-контекст по Wi-Fi БЕЗ разрешения на геолокацию** (спец §3.2): сеть опознаётся локальным хешем адреса шлюза/DHCP из `LinkProperties` (`context/NetworkIdentity`, SHA-256 с доменным префиксом, 16 hex; сырой адрес не хранится). SSID читается ТОЛЬКО как подпись и только если разрешение уже выдано ради карты — сопоставление от него не зависит. Честное ограничение (в KDoc и в UI): одинаковый шлюз `192.168.1.1` у разных сетей даёт одинаковый токен, поэтому привязка = подтверждаемая пользователем подсказка, а не доказательство места. GPS для контекста НЕ используется никогда (единственная подписка на локацию — явная запись трека). State machine чистая: `context/ContextMachine` (`AUTO_KNOWN / AUTO_UNCERTAIN(grace) / AUTO_TRANSIT / NO_CONTEXT / MANUAL`), grace по умолчанию 3 мин (1/2/3/5 в Настройках) отсчитывается от ПОТЕРИ знакомой сети и не перезапускается сменой «нет сети»↔«чужая сеть»; ручной выбор живёт в DataStore и переживает перезапуск сервиса, снимается командой «Вернуться к авто»
- **Baseline admission pipeline** (спец §4.2) — `baseline/BaselineAdmission`, 7 условий В ПОРЯДКЕ спеца, возвращается ПЕРВОЕ невыполненное (иначе пользователю называют симптом вместо причины): обучение профиля, надёжность контекста, свежесть потока (тот же порог 10 с, что в UI), Поиск/эксперимент, карантин, пригодность статистики, ручная заморозка. Сырые данные пишутся ВСЕГДА; вердикт лежит в `samples.baselineExcluded` (ключи — контракт на диске, только дополняются), и только `baselineExcluded IS NULL` кормит baseline. Карантин 30 мин отсчитывается от КОНЦА эпизода отклонения (`QuarantineWindow` двигает дедлайн, пока превышение держится). Условие «статистика пригодна» сознательно слабое (не-конечные/отрицательные значения, нулевой счёт, относительная погрешность >50 %) — строгий критерий по dead-time/pile-up требует замеров на приборе
- **Четыре уровня достоверности** (спец §2) — `ui/logic/Evidence` (MEASURED / CALCULATED / STATISTICALLY_DETECTED / INTERPRETATION), рендер = тишайшая приглушённая мета-подпись рядом со значением (`ui/components/EvidenceTag`). Уровни не смешиваются в одной фразе: доза = изм., доза за сутки = расчёт, статус baseline = стат., колонка «кандидат» в таблице пиков = гипотеза. Сырые измерения на Мониторе метку не носят там, где она была бы шумом
- **«Почему?»** (спец §17) — шторка с Монитора; сборка текста чистая (`ui/logic/WhyExplain`, JVM-тесты на формулировки): текущее значение, счёт с 1σ, свежесть потока, профиль и как он выбран, P10–P90 + медиана + P25–P75 + MAD, длительность и n, порог тревоги, учится ли фон прямо сейчас и почему нет, сколько времени исключено и по каким причинам, и честное «спектральная аномалия не оценивается» (это этап 4)
- **Энергетические окна** (спец §7) — `analysis/EnergyWindows`, по умолчанию 100–300 / 300–700 / 700–1500 кэВ. Границы — ПАРАМЕТР АНАЛИЗА, а не физические категории излучения: редактируются на Спектре, хранятся в DataStore (`energy_windows_kev`, формат `100:300,300:700`), уезжают в отчёт эксперимента. Край окна НЕ дробится: канал целиком относится к окну, если его центр попал внутрь [E₁,E₂) — дробный счёт перестал бы быть пуассоновским (та же причина, по которой `SpectrumMerge` отказывается ребиннить), поэтому вместе с суммой возвращается реально покрытый диапазон. R = C/t, σ_R = √C/t; индекс R_low/R_high = C_low/C_high (общее t сокращается), σ = index·√(1/C_low+1/C_high); индекс — ОПИСАНИЕ СОСТАВА спектра, в UI обязана стоять фраза «не мера опасности»
- **Проекция дозы** (спец §6) — `analysis/DoseProjection`: Ḋ̄ = D_окна / t_ИЗМЕРЕНИЙ (не настенного времени), за год = Ḋ̄ · 8766 ч. Формулировка задана спецификацией и запинена тестом: «если средняя измеренная внешняя фотонная мощность дозы останется такой же — за год ≈ X»; называть это годовой (эффективной) дозой ЗАПРЕЩЕНО, рядом перечислено, что не входит. Меньше часа реальных измерений — проекции нет вовсе
- **A/B эксперимент** (спец §9, §16) — `experiments` + `experiment_runs` (Room v7), экран `ui/screens/AbExperimentScreen` (вход — чип «A/B ▸» со Спектра, навигация самодостаточна). Протокол: сценарий → геометрия описывается ОДИН раз и показывается перед каждым следующим прогоном → прогон A → прогон B → сравнение. Спектр прогона = разность снимков конца и начала (`SpectrumCompare.extractInterval`), сохраняется с `origin='derived'` — такие строки исключены из Истории, из «последнего спектра прибора» и из радонового тренда (иначе короткий интервал попал бы в цепочку накоплений). Математика `analysis/AbAnalysis`: net = G − B·(t_G/t_B), σ_net = √(G + B·(t_G/t_B)²) [IAEA R4, вывод в KDoc]; статистика ПУАССОНОВСКАЯ по счёту: < 25 импульсов в прогоне → отношение правдоподобия (девианс 2[G·ln(G/Ĝ)+B·ln(B/B̂)], Ĝ = (G+B)·t_G/(t_G+t_B)), иначе χ²-подобный z = нетто/σ; считаются обе, использованная названа в результате и в отчёте. Полный спектр — сумма поканальных девиансов/χ² → Wilson–Hilferty, ОДНОСТОРОННИЙ (статистика ниже ν = согласие, а не различие, z зажат снизу нулём). Доза сравнивается как средние с SEM и помечена вспомогательной: секундные показания прибора коррелированы, её неопределённость — оценка снизу. Вердикты ТОЛЬКО `consistent / changed / strong evidence of change` (|z| 2 и 4), «% похожести» запрещён тестом. Старт прогона поднимает `ServiceStatus.experiment` — тот же флаг, что у Поиска; флаг теперь мультиисточниковый (`onExperiment(source, name)`), гаснет только когда снят последним источником, а сервис берёт условие 4 admission-пайплайна прямо из него. Расстояние: серия сравнивается с 1/r² ТОЛЬКО рядом с предупреждением о геометрии/рассеянии/фоне; экранирование: коэффициенты ослабления не выводятся. Экран помечен «экспериментальная функция» до валидации на приборе (спец §24)
- **Воспроизводимость** (спец §22) — `analysis/AlgorithmVersions` единственный источник версий алгоритмов, числа ЗАПИНЕНЫ тестом: смена математики обязана приходить вместе с осознанным бампом версии. Производный снимок несёт `spectra.analysisMeta` (плоский JSON `data/JsonMap`: метод, версии алгоритмов, нормализация, метод фона, источники) — компаратор A−B, объединение, прогоны A/B; эксперимент хранит `algorithmVersion` + `params` (окна, порог переключения статистики, пороги вердикта) и НИКОГДА их не переписывает (старые выводы остаются сравнимыми). Экспорт: RC-XML — метаданные в `SampleInfo/Note`, N42 — в `<Remark>` первыми элементами, эксперимент — текстовый отчёт со всеми прогонами, вердиктами и параметрами. `JsonMap` вместо `org.json` намеренно: колонки читает чистый JVM-код в тестах без Android-заглушки
- Room v7 со схемами в `app/schemas` (миграции проверяются JVM-тестом на sqlite-jdbc без инструментации; v6→v7 = `experiments` + `experiment_runs` с каскадом прогонов и `spectra.analysisMeta`, у существующих строк NULL — они писались до метаданных обработки, и придумывать им метод было бы враньём); сессии измерений не дублируют данные — сводки агрегируют `samples` по диапазону времени. **Колонки `samples.placeId` / `measurement_sessions.placeId` в v6 СОЗНАТЕЛЬНО сохранили имя**: `ALTER TABLE … RENAME COLUMN` доступен с SQLite 3.25 (API 30), а minSdk 26 → пришлось бы перестраивать таблицу с миллионами строк ради косметики. Имя `profileId` даёт `@ColumnInfo(name = "placeId")`. Профили в v6 получают id старых мест — привязка измерений не рвётся. История умеет переназначить профиль сессии задним числом: переезжают и сессия, и её сэмплы, и ЗАВИСЯЩАЯ ОТ ПРОФИЛЯ часть вердикта (`learning_off`); причины, описывающие само измерение, не переписываются — поздняя правка места не делает плохое измерение хорошим
- Единицы отображения мкЗв/ч⇄мкР/ч (×100) — только на выводе через `DoseFormat`, сырые значения неизменны
- Карта — osmdroid 6.1.20 (Apache-2.0), растровые тайлы OSM standard (ADR 003; MapLibre GL Native выкинут — серый экран на целевом устройстве ДВАЖДЫ: сперва Vulkan-пакет, затем `android-sdk-opengl` 13.4.1; GPU-конвейер чужого движка вслепую не чинится). У osmdroid нет своей поверхности рендера — Canvas на штатном hardware-слое. Обязателен отличительный User-Agent (имя пакета; дефолтный «osmdroid» на серверах OSM заблокирован) и никакого bulk-скачивания — офлайн-предзагрузка района СОЗНАТЕЛЬНО не делается, есть только кэш просмотренного (512 МБ в cacheDir). Тёмная тема — цветовая матрица «инверсия + поворот тона 180°» (голый INVERT_COLORS красит лес пурпурным), светлая — без фильтра; матрица чистая в `ui/logic/MapTiles.kt`. Нативного кода в APK не осталось, ABI-фильтр arm64 убран. Трек красится 4-ступенчатой янтарной рампой с квантильными порогами (P25/P50/P75 видимого трека), рендер ≤2000 точек одним батч-оверлеем (не Marker-ы), попадание тапа — по пикселям последнего кадра через чистую `TrackMap.nearestIndex`; вся математика карты — `ui/logic/TrackMap.kt`, osmdroid-типы не покидают `ui/map/`. Экран показывает честный статус тайлов («загружаются / готово / ошибка сети») и называет причину, если не пришло ни одного тайла (подсказка про разрешение «Сеть» в GrapheneOS) — мы в поле без логов. Hotspot-события несут baseline typical в `param1` (нЗв/ч, как deviation).
- Поиск-фидбек: клики — синтез PCM на лету (streaming AudioTrack, USAGE_MEDIA, Пуассоновы интервалы со средним = CPS, кэп 40/с), вибро — один пульс на новую σ-ступень от +2σ над локальным фоном с гистерезисом 1σ; работает только при активном экране Поиска, молчит под DND и при обрыве потока. Клики играют на потоке МЕДИА (`USAGE_MEDIA`): прежний `USAGE_ASSISTANCE_SONIFICATION` = STREAM_SYSTEM, который система глушит в режиме «без звука/вибрация» и вешает на ползунок звонка — это и была полевая тишина. ОТКАЗ в аудиофокусе больше не глушит (это не решение пользователя); молчим только при реальной потере фокуса после выдачи. Кадровый цикл вынесен в чистый `ClickEngine` (JVM-тесты: ненулевая частота даёт ненулевые сэмплы, число кликов держит частоту, любой реалистичный CPS 1..200 слышен). Вибро без записанного локального фона НЕ РАБОТАЕТ никогда (σ считается от фона) — экран обязан это говорить: под переключателями одна честная строка с реальной причиной тишины (`FeedbackReason`). Настройки → «Проверка»: «Проверить звук» (5 кликов мимо всех гейтов) и «Проверить вибрацию» — каждая называет конкретную помеху; это единственный способ отделить движок от обвязки в полевом отчёте. «Тон по энергии» — 3 ступени высоты клика (<300 / 300–1000 / >1000 кэВ → 1,8 / 2,6 / 3,4 кГц) по среднему кэВ последнего 5-с среза спектрограммы; срез старше 15 с или нет потока → обычные клики (`EnergyTone` в `ui/logic/SearchFeedback.kt`). Тревога движка — уведомление на отдельном канале «Тревога» (IMPORTANCE_HIGH, системный alarm-звук; пользователь настраивает через системные настройки канала), ровно одно на эпизод. Чистая математика — `ui/logic/SearchFeedback.kt`
- Опрос DATA_BUF: 1 Гц обычно, 500 мс пока открыт экран Поиска (`FastPollHub` в AppGraph по образцу `SpectrumHub`, refcount attach/detach; сервис выбирает период, UI на device-слой не смотрит). Это уменьшает ЗАДЕРЖКУ ПОДБОРА записей (~0,5 → ~0,25 с), а НЕ частоту измерений — прибор всё равно делает запись раз в секунду; формулировки в UI и KDoc не должны обещать «2 измерения в секунду». Цикл опроса последовательный на однозапросном `ProtocolClient` — тики не накапливаются; пустой ответ DATA_BUF при 2 Гц штатен и не считается сбоем/пропуском seq. Ускорение только при RESUMED-экране Поиска, в фоне и на других вкладках — 1 Гц
- Полноэкранный живой график (тап по карточке Монитора) — ГРАФИК ВЛАДЕЕТ ЭКРАНОМ: рендерится поверх таб-бара (`AppRoot`), сам держит system-bar insets, оси подписаны ВНУТРИ поля (график от края до края). Портрет: шапка (закрыть · заголовок · живое значение ±погрешность · чип свежести/паузы) → поле графика на всю оставшуюся высоту → полоса распределения → две строки статистики (мин/P10/медиана/P90 · макс/σ/n/окно) → чипы (периоды 15м…30д, лин/лог, «⌖ сейчас») → одна приглушённая строка уровней достоверности. Ландшафт: поле на весь экран, статистика одной моно-строкой в шапке, управление плавает чипами. Анатомия: медиана корзины (линия) + конверт мин–макс (светлая заливка) + mean±σ (плотная) + полоса привычного фона профиля с пунктиром медианы + именованная «L1 …» + янтарные эпизоды с длительностью + сырые точки при корзине ≤5 с; курсор по long-press с drag даёт время, значение ±σ, n и «×N к привычному». Производительность: ОДИН запрос в БД на смену окна (IO, debounce 250 мс, `collectLatest` отменяет), загрузка с запасом в четверть окна, жесты только перепроецируют неизменяемый снимок; бюджет запроса фиксирован (≤200 корзин × 12 под-корзин) — 30 дней стоят столько же, сколько 15 минут; три раздельных draw-узла (статичный/серия/курсор) с `drawWithCache`, пиксели корзин — примитивные массивы, курсор читается через `State` прямо в draw (скраб не вызывает рекомпозицию), живое значение — отдельный composable со своим 1 Гц тикером. Вся математика — чистый JVM: `ui/logic/DoseChartModel` (свёртка корзин, оконная статистика, эпизоды), `DoseHistogram` (распределение по измеренным секундам), `DoseScale` (лин/лог; на логе ноль НЕ рисуется — считается и называется числом отброшенных корзин), `ChartProjection`, `ChartCursor`, `ChartWindow`. Кастомизация меню: вкладки как CSV в DataStore (`!`-префикс = скрыта), парсинг и гард «Главная + минимум одна» — `ui/logic/NavConfig.kt`; блоки Монитора — булевы флаги (`MonitorBlocks`)
- **Тренд — Theil–Sen** (граф-спец §23, `ui/logic/TrendFit`): β̂ = медиана попарных наклонов (xⱼ−xᵢ)/(tⱼ−tᵢ) по медианам ПРИСУТСТВУЮЩИХ корзин, единицы мкЗв/ч на час; OLS остался только как `researchOlsSlope` для исследовательского сравнения (один всплеск +5 мкЗв/ч уводит OLS с 0,6 до >3,9, Theil–Sen не двигает). Тренда НЕТ (`тренд недоступен`), пока корзин <12 или размах <10 мин — оба порога ИНЖЕНЕРНЫЕ, не научные константы; выше 250 точек — детерминированное прореживание фиксированным шагом (первая и последняя сохраняются, случайности нет). Тренд ОПИСАТЕЛЬНЫЙ: ни значимости, ни доверительного интервала (1 Гц поток автокоррелирован, интервал по τ Кендалла был бы в разы уже правды). Гистограмма окна — Freedman–Diaconis h = 2·IQR·n^(−1/3) с клампом [8, 40] и округлением границ (кламп — ПРОДУКТОВАЯ эвристика, §14 прямо это говорит) и тремя обязательными fallback'ами: IQR = 0 → правило √n, наблюдений <20 → «недостаточно данных для распределения» вместо картинки, все значения равны → одна корзина; n в FD — число под-корзин (честное n порядковых статистик), ось Y подписана тем, что реально считает: «секунд измерений (1 Гц)»
- **Аномалии: показываем только описания, тест держим за opt-in** (граф-спец §35/§36) — в UI живёт `analysis/DescriptiveDeviation`: «медиана сместилась», «разброс шире», «вне исторического P10–P90 профиля», «короткий всплеск», каждая фраза несёт числа, на которых стоит (для «Почему?»); σ, p-value, проценты уверенности и слово «значимо» запрещены тестом. Кандидат формального теста (`analysis/AnomalyStatistics`, весь под `@ExperimentalRadiationStatistics`, opt-in уровня ERROR) — Mann–Whitney U + Kolmogorov–Smirnov с ОБЯЗАТЕЛЬНОЙ поправкой на автокорреляцию: N_eff = N/τ, где τ = 1 + 2Σρ_k (обрыв на первом неположительном ρ, Geyer) либо AR(1)-форма (1+ρ₁)/(1−ρ₁). Без поправки сканирование стационарного ряда даёт 21 % тревог = ~154 в сутки, с поправкой 0 из 328 при τ̄ = 9,1 (харнесс `analysis/validation/`, детерминированные синтетические ряды Пуассон+интегратор; ступенька ×1,5 ловится 12/12 за 300 с, ×1,02 — 3/12). Пока не измерены FP-rate и power на РЕАЛЬНЫХ записях RC-110 (критерии и формат CSV — `docs/analysis/trend-and-anomaly.md`), из теста в UI не уходит ничего
- Спектр: экран опрашивает спектр «с последнего сброса» раз в 5 с через тот же однозапросный клиент (перемежается с 1 Гц DATA_BUF; мост UI↔сервис — `SpectrumHub`); анализ пиков — чистый JVM в `app/.../analysis/`: локальный максимум сглаженного ряда + боковой континуум + Poisson-SNR при FWHM(E)=8%·√(662·E); подсказки изотопов всегда «возможное совпадение», уверенность максимум «средняя», «обнаружен» не пишется никогда
