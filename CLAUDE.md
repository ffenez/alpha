# radiacode

Современное Android-приложение для дозиметра-спектрометра RadiaCode 110: подключение по BLE, живые показания, спектр, журнал. Замена официального приложения с упором на приватность и качество UI.

## Stack

- Kotlin, Jetpack Compose (Material 3), coroutines/Flow; minSdk 26
- BLE: Kable (Apache-2.0) + собственный порт протокола cdump/radiacode (MIT, атрибуция обязательна)
- Хранение: Room (SQLite)
- Карта: MapLibre GL Native + тайлы OpenFreeMap; геолокация — LocationManager (не Fused)

## Invariants

- Данные измерений и координаты не покидают устройство. Никакой телеметрии, аналитики, крэш-репортинга в сеть. Единственный разрешённый сетевой трафик — анонимная загрузка тайлов карты (с агрессивным кэшем; тайл-запросы не должны содержать ничего, кроме координат тайла).
- Никаких зависимостей от Google Play Services / Firebase — целевое устройство GrapheneOS без GMS.
- BLE-протокол RadiaCode реверс-инжинирен сообществом; собственный код протокола писать по документации/идеям, код копировать только из совместимых по лицензии источников с атрибуцией (GPL-код не копировать).
- Дозиметрические величины: хранить сырые значения и единицы (мкЗв/ч, cps), не терять точность при конвертации.

## Commands

- Сборка: `JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:assembleDebug` (свежий APK автоматически копируется в `apk/app-debug.apk`)
- Тесты: `JAVA_HOME=/home/dev/.local/jdk ./gradlew test` (JVM-тесты :protocol и :app)
- Lint: `JAVA_HOME=/home/dev/.local/jdk ./gradlew :app:lintDebug`

## Key decisions

- Протокол — чистый Kotlin-порт cdump/radiacode; Open-RadiaCode-Android без лицензии — только идеи, не код (ADR 001)
- Один запрос в полёте, матчинг по эхо заголовка; канонический SPEC_ACCUM = 0x205. Пропуск seq в DATA_BUF не рвёт разбор (записи самоограничены — ресинк, счётчик `seqGaps` в `DataBufResult`, идея qtradiacode); несовпадение эха = хвост прежнего обмена → слить ожидающие ответы и ровно один повтор со свежим seq после 100 мс
- Устройство держит одного BLE-клиента: сосуществование с официальным приложением невозможно, это ограничение UX
- Непрерывное измерение — foreground service + запрос исключения из battery optimization
- UI — дизайн-система «Научный терминал» (вариант F, docs/design/design-language.md): IBM Plex Sans/Mono (OFL, бандлятся), тёмная тема основная + светлая по системе, карточки 14dp/рамка 1dp, каждая величина с погрешностью, оси графиков всегда подписаны; токены в `app/.../ui/theme`, компоненты в `app/.../ui/components`; экраны тонкие, вся тестируемая логика UI — в `ui/logic` (чистый JVM)
- Baseline — взвешенная перцентильная полоса P10–P90 по минутным корзинам места (окно 14 дней, отсечка >3×медианы, активация после 3 ч); отклонение = величина И длительность (`PersistenceTracker`); движок чистый JVM в `app/.../baseline/` (ADR 002)
- Room v2 со схемами в `app/schemas` (миграции проверяются JVM-тестом на sqlite-jdbc без инструментации); сессии измерений не дублируют данные — сводки агрегируют `samples` по диапазону времени
- Единицы отображения мкЗв/ч⇄мкР/ч (×100) — только на выводе через `DoseFormat`, сырые значения неизменны
- Карта — MapLibre GL Native (Vulkan-пакет `org.maplibre.gl:android-sdk`) + стили OpenFreeMap `dark`/`positron` по теме, без ключей и аккаунтов; ambient-кэш тайлов 512 МБ (повторные районы офлайн); INTERNET в манифесте существует только для тайлов. Трек красится 4-ступенчатой янтарной рампой с квантильными порогами (P25/P50/P75 видимого трека), рендер ≤2000 точек (downsampling; все числа — по полному ряду); GeoJSON и вся логика карты — чистый JVM в `ui/logic/TrackMap.kt`, MapLibre-типы не покидают `ui/map/`. Hotspot-события несут baseline typical в `param1` (нЗв/ч, как deviation). Debug-APK собирается только под arm64-v8a (целевой Pixel; MapLibre ≈12 МБ на ABI)
- Поиск-фидбек: клики — синтез PCM на лету (streaming AudioTrack, USAGE_ASSISTANCE_SONIFICATION, Пуассоновы интервалы со средним = CPS, кэп 40/с), вибро — один пульс на новую σ-ступень от +2σ над локальным фоном с гистерезисом 1σ; работает только при активном экране Поиска, молчит под DND/без аудиофокуса и при обрыве потока. «Тон по энергии» — 3 ступени высоты клика (<300 / 300–1000 / >1000 кэВ → 1,8 / 2,6 / 3,4 кГц) по среднему кэВ последнего 5-с среза спектрограммы; срез старше 15 с или нет потока → обычные клики (`EnergyTone` в `ui/logic/SearchFeedback.kt`). Тревога движка — уведомление на отдельном канале «Тревога» (IMPORTANCE_HIGH, системный alarm-звук; пользователь настраивает через системные настройки канала), ровно одно на эпизод. Чистая математика — `ui/logic/SearchFeedback.kt`
- Полноэкранный живой график (тап по карточке Монитора): оконная математика pan/pinch/live-follow — чистый JVM `ui/logic/ChartWindow.kt`; TrendChart получил опциональные жесты (pad-геометрия жестов совпадает с отрисовкой) и режим fill-height. Кастомизация меню: вкладки как CSV в DataStore (`!`-префикс = скрыта), парсинг и гард «Главная + минимум одна» — `ui/logic/NavConfig.kt`; блоки Монитора — булевы флаги (`MonitorBlocks`)
- Спектр: экран опрашивает спектр «с последнего сброса» раз в 5 с через тот же однозапросный клиент (перемежается с 1 Гц DATA_BUF; мост UI↔сервис — `SpectrumHub`); анализ пиков — чистый JVM в `app/.../analysis/`: локальный максимум сглаженного ряда + боковой континуум + Poisson-SNR при FWHM(E)=8%·√(662·E); подсказки изотопов всегда «возможное совпадение», уверенность максимум «средняя», «обнаружен» не пишется никогда
- Спектрограмма — интервальные срезы (накопление − предыдущее, кламп ≥0; сброс переармирует базу) раз в 5 с в `SpectrogramStore` (кольцо ~2 ч только в памяти, персистентная запись = снимки спектра); 96 геометрических полос 20–3000 кэВ, яркость = лог-нормировка внутри столбца; рампа карты, на тёмной теме обращённая — светлота растёт с интенсивностью; чистая математика — `analysis/Spectrogram.kt`
- Радон-индикатор — ВСЕГДА «относительный индикатор радоновых продуктов, не Бк/м³»: ROI-неты Bi-214 609,3 / Pb-214 351,9 кэВ (окно ±FWHM, боковой континуум) из разностей соседних авто-снимков, прореженных до 1/час (`analysis/RadonTrend.kt`); сервис ради него опрашивает спектр раз в 10 мин даже без наблюдателя SpectrumHub (автосейв сохраняет)
- Объединение/продолжение снимков — `analysis/SpectrumMerge`: канальная сумма + сумма Δt, только при калибровках в допуске ≤5 кэВ; ребиннинг для суммы сознательно НЕ предлагается (дробные счета — не Пуассон), отказ отсылает к «Скоростям счёта». «Продолжить накопление» — сумма для показа/сохранения, прибор копит независимо (баннер предупреждает о двойном счёте без сброса)
- Полёт: `track_points.altitudeMeters` (схема v5, nullable); полёт = ≥2 мин непрерывно >3000 м, разрыв фиксов >60 с рвёт серию (`ui/logic/FlightDetect.kt`); в деталке — доза и высота двумя стыкованными графиками с ОБЩЕЙ осью времени, двойная ось запрещена; «×N» — медианы эшелона/земли одной записи
- Форматы обмена спектрами — чистый Kotlin в `data/export/` (clean-room, GPL-код не использовался): RC-XML FormatVersion 120920 (writer + толерантный парсер; MeasurementTime в СЕКУНДАХ, времена — локальные без зоны) и N42-2011 (только честные поля, live=real time); импорт хранится в `spectra` c origin='import' (v4: origin/label) и не смешивается с приборными данными; сравнение снимков — чистый JVM `analysis/SpectrumCompare` (интервал A−B с Δt·1000 ровно один раз — не повторять ms/s-баг комьюнити-тулов; скорости в имп/с с σ=√N-пропагацией, допуск калибровок 5 кэВ, иначе ребиннинг по перекрытию бинов)
