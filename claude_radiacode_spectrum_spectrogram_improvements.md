# ТЗ для Claude Code: графики, спектрограмма и научный анализ спектра

## Цель

Доработать экраны временных графиков, спектрограммы и анализа спектра RadiaCode так, чтобы:

- визуализация была чистой и однозначной;
- спектрограмма выглядела как непрерывная карта «энергия × время», а не как несколько широких спектров рядом;
- пропуски данных нельзя было спутать с нулевым сигналом;
- масштабирование графиков не влияло на исходные измерения и научные расчёты;
- идентификация нуклидов учитывала не только совпадение энергии отдельного пика, но и согласованность нескольких линий и их интенсивностей.

---

# 1. Временные графики: убрать визуальные артефакты

На графиках мощности дозы и скорости счёта сейчас встречаются вертикальные области с диагональной штриховкой. Они визуально воспринимаются как ошибка рендера или случайная сетка.

## Требование

Если штриховка обозначает:

- отсутствие данных;
- неполное покрытие;
- разрыв Bluetooth/потока;
- период, исключённый из статистики;

то не использовать выраженную диагональную штриховку как основной способ отображения.

Использовать спокойную нейтральную полупрозрачную область.

При тапе/курсоре должна отображаться причина, например:

- `нет данных`;
- `неполное покрытие`;
- `поток прерван`.

Если участок действительно означает отсутствие данных, он НЕ должен отображаться как значение 0.

Желательно явно отмечать границу начала данных:

`запись началась 18:17`

---

# 2. Последнее значение справа как в TradingView

Для временных графиков добавить маркер последнего значения на правой границе.

Пример:

```text
──────────────●  0,10
```

Для мощности дозы:

`0,10 мкЗв/ч`

Для скорости счёта:

`10,4 с⁻¹`

## Поведение

В обычном состоянии:

- последняя точка видима;
- справа от неё находится компактный value label;
- допускается короткая горизонтальная направляющая до правой границы.

При активном курсоре:

- основной label показывает значение в позиции курсора;
- показывается соответствующее время;
- текущее последнее значение можно оставить вторичным маркером.

Не растягивать лишнюю горизонтальную линию через весь график, если она не несёт дополнительной информации.

---

# 3. Сетка временных графиков

Использовать очень слабую major grid.

Сетка не должна конкурировать с данными.

Для обычных временных графиков:

- вертикальные major lines — по временным делениям;
- горизонтальные major lines — по подписанным значениям Y;
- minor grid использовать только при реальной необходимости.

---

# 4. Спектрограмма: исправить time binning

Текущая проблема: на коротком окне спектрограмма состоит из нескольких чрезвычайно широких временных колонок.

Это делает её похожей на несколько спектров, поставленных рядом, а не на time-energy heatmap.

Научная модель:

- X = время;
- Y = энергия, кэВ;
- цвет = интенсивность в соответствующем time-energy bin.

## Требование

Количество отображаемых временных колонок должно зависеть от ширины графика и выбранного временного окна.

Цель:

примерно 60–150 отображаемых time bins на полезную ширину экрана.

Ориентировочные значения:

- 1 мин: ~1–2 с/bin;
- 5 мин: ~3–5 с/bin;
- 15 мин: ~10–15 с/bin;
- 1 ч: ~30–60 с/bin;
- 2 ч: ~1–2 мин/bin.

Это UX-ориентиры, а не физические константы.

Фактический алгоритм лучше рассчитывать от:

`visibleDuration / targetColumnCount`

с последующим округлением до удобного шага.

Одна колонка не должна занимать сотни пикселей.

---

# 5. Energy binning спектрограммы

Не смешивать raw detector channels и display bins.

Исходные данные сохранять без потерь.

Для отображения разрешается агрегировать соседние энергетические каналы.

## Важно

Границы энергетических bins должны быть одинаковыми для всех временных колонок текущего окна.

Нельзя независимо менять energy bins для каждого time bin: иначе структуры спектра начнут визуально перемещаться и деформироваться во времени.

Допускается выбирать display energy binning в зависимости от:

- масштаба;
- разрешения экрана;
- общего количества статистики в текущем окне.

---

# 6. Цветовая шкала спектрограммы

Вместо нескольких отдельных цветных квадратиков желательно использовать непрерывную colorbar:

```text
0  ░▒▓████  0,6 имп/с
```

В информационном окне `ⓘ` явно показывать:

- тип цветового преобразования;
- единицу интенсивности;
- ширину time bin;
- ширину/правило energy bin.

Если используется logarithmic mapping, корректно обрабатывать нулевые значения: log(0) не определён.

Не маскировать отсутствие данных цветом, соответствующим нулевой интенсивности.

---

# 7. Нижняя линия под спектрограммой

Бирюзовая линия мощности дозы сейчас визуально может восприниматься как часть heatmap.

Предпочтительный вариант:

сделать отдельный синхронизированный mini-chart под спектрограммой высотой примерно 48–64 dp.

Он должен иметь:

- ту же временную ось X;
- собственную единицу `мкЗв/ч`;
- курсор, синхронизированный со спектрограммой.

Альтернатива — полностью убрать линию и показывать dose/CPS только при выборе временной колонки.

Предпочтителен отдельный mini-chart.

---

# 8. Сетка спектра: major/minor в Log

Для обычного спектра добавить полноценную логарифмическую сетку.

В режиме Log:

- major ticks: 1, 10, 100, 1k, 10k, 100k…;
- minor ticks: 2…9 × 10^n;
- подписи только у major ticks;
- minor grid значительно слабее major grid.

Это позволяет визуально оценивать значения между степенями десяти.

В режиме Linear оставить преимущественно major grid. Не превращать мобильный экран в плотную миллиметровую сетку.

Для heatmap-спектрограммы энергетическую сетку делать намного слабее, чем для обычного спектра.

---

# 9. Добавить режим Pow

Для отображения спектра оставить:

`Лин | Log | Pow`

Pow — только преобразование визуального масштаба.

Использовать:

`y_display = x^γ`

где:

- γ = 1 — исходный linear;
- γ = 1/2 — sqrt;
- γ = 1/3 — cube root;
- меньшие γ сильнее сжимают динамический диапазон и визуально усиливают слабые структуры.

## UI

После выбора `Pow` показывать slider:

`1.00 ─────●──── 0.10`

и текущее значение:

`γ = 0.50`

Добавить быстрые пресеты:

- 1/2;
- 1/3;
- 1/4.

По умолчанию разумно ограничить обычный рабочий диапазон примерно γ = 1…0.2.

γ = 0.1 (1/10) можно оставить как расширенный предел, но это очень агрессивное отображение: оно заметно подчёркивает шум и статистические флуктуации.

## Критически важно

Pow, Linear и Log НЕ должны менять:

- исходные counts;
- peak detection;
- net peak area;
- baseline/continuum estimation;
- SNR;
- статистические ошибки;
- идентификацию нуклидов.

Это исключительно display transform.

В `ⓘ` явно написать об этом.

# 10. Проверка нескольких линий нуклида

Существующий подход «энергия пика совпала с известной линией → кандидат» недостаточен для уверенной идентификации.

Добавить multi-line consistency analysis.

IAEA рекомендует при γ-спектрометрии:

1. определять энергии фотопиков;
2. интегрировать области фотопиков;
3. вычитать baseline/continuum и получать net peak area;
4. при наличии нескольких γ-линий использовать их совместно и учитывать отношения линий.

Не использовать высоту одного канала как интенсивность линии.

Использовать net peak area.

---

# 11. Отношение интенсивностей линий

Для двух линий одного кандидата:

наблюдаемое отношение:

`R_obs = A1_net / A2_net`

где `A_net` — net peak area после вычитания continuum.

Нельзя напрямую сравнивать его только с отношением табличных gamma emission probabilities.

Детектор имеет энерго-зависимую эффективность.

Ожидаемое отношение имеет вид:

`R_expected = (Iγ1 × ε(E1)) / (Iγ2 × ε(E2))`

где:

- Iγ — вероятность/интенсивность соответствующей γ-линии;
- ε(E) — эффективность регистрации full-energy peak для данной энергии и соответствующей геометрии.

Сравнение проводить с учётом статистической неопределённости.

Не использовать произвольное фиксированное правило вроде `±20 %` как универсальный научный критерий.

---

# 12. Ограничение RadiaCode

Не заявлять количественную коррекцию intensity ratio по эффективности, если для конкретного прибора/геометрии нет достоверной efficiency curve.

Если такой калибровки нет:

- показывать наблюдаемое отношение;
- показывать табличное emission ratio отдельно;
- явно отмечать, что прямое сравнение ограничено неизвестной относительной эффективностью детектора.

Не создавать фиктивную efficiency curve.

Если в будущем появится экспериментальная calibration/response model — архитектура должна позволять подключить её.

---

# 13. UI проверки кандидата

При открытии строки кандидата отображать примерно:

```text
Гипотеза: X-xxx

Линии
энергия      найдено       ожидаемая роль
xxx кэВ         ✓             сильная
xxx кэВ         ✓             средняя
xxx кэВ         —             слабая

Отношение линий
наблюдаемое     0,XX ± 0,XX
ожидаемое*      0,XX

*с учётом относительной эффективности детектора,
если доступна её калибровка

Совместимость: хорошая
```

Если efficiency correction недоступна:

```text
Отношение линий: информационно

Точное сравнение ограничено:
относительная эффективность детектора
для этих энергий не откалибрована.
```

---

# 14. Отсутствующая линия не означает автоматическое опровержение

Нельзя делать:

`одна ожидаемая линия отсутствует → нуклид исключён`.

Перед этим учитывать:

- ожидаемую интенсивность линии;
- статистику измерения;
- continuum;
- detection threshold;
- перекрытие с соседними пиками;
- энергетическое разрешение детектора;
- возможность spectral interference.

Слабая линия может быть статистически неразличима.

---

# 15. Уровни уверенности идентификации

Разделить понятия.

### Кандидат

Одна или несколько энергий совместимы с библиотечными линиями.

### Поддерживаемая гипотеза

Несколько ожидаемых линий согласуются с измерением и статистикой.

### Более сильная спектральная совместимость

Согласуются:

- энергии;
- несколько линий;
- net areas;
- относительные интенсивности с учётом efficiency correction, если она доступна;
- отсутствуют сильные противоречащие линии.

Не использовать категоричное:

`обнаружен K-40`

только из-за совпадения одного пика.

Предпочитать формулировки:

- `кандидат K-40`;
- `спектр совместим с K-40`;
- `гипотеза поддерживается несколькими линиями`.

# 16. Научная архитектура расчётов

Строго разделить pipeline:

```text
RAW COUNTS
    ↓
energy calibration
    ↓
continuum/background estimation
    ↓
peak detection
    ↓
peak fitting / integration
    ↓
net peak area + uncertainty
    ↓
energy matching
    ↓
multi-line candidate analysis
    ↓
intensity-ratio consistency
    ↓
confidence / hypothesis UI
```

Отдельно:

```text
RAW/PROCESSED DATA
        ↓
DISPLAY TRANSFORM
Lin / Log / Pow
        ↓
GRAPH ONLY
```

Display transform никогда не должен попадать обратно в научный pipeline.

# 18. Критерии готовности

Работа считается завершённой, если:

- 15-минутная спектрограмма больше не состоит из 2–3 гигантских колонок;
- изменение временного окна автоматически меняет display time binning;
- отсутствие истории нельзя принять за нулевой сигнал;
- последний sample временного графика имеет компактный label справа;
- Log spectrum имеет major/minor logarithmic grid;
- Pow меняет только визуализацию;
- изменение γ не меняет найденные пики, SNR и net areas;
- кандидат по нуклиду может проверяться по нескольким линиям;
- intensity ratio считается по net peak areas;
- efficiency correction применяется только при наличии обоснованной efficiency model;
- слабая отсутствующая линия не приводит автоматически к отказу от кандидата;
- UI различает совпадение энергии, кандидата и спектрально поддерживаемую гипотезу.

# Научные основания

Для проверки научной части ориентироваться прежде всего на документы IAEA по gamma spectrometry.

IAEA описывает процедуру идентификации через определение энергий фотопиков, интегрирование областей пиков с вычитанием continuum и использование отношений линий, когда изотоп испускает несколько gamma photons.

Для количественной связи counts с активностью также учитываются gamma abundance и detector efficiency для соответствующей энергии.

Следовательно, простое сравнение высот двух пиков или отношение net counts без учёта energy-dependent efficiency не должно выдаваться приложением за строгую проверку branching/intensity ratio.

Основной источник:
IAEA, Production, Quality Control and Clinical Applications of Radiosynovectomy Agents, gamma-ray spectrometry section:
https://www-pub.iaea.org/MTCD/Publications/PDF/PUB1915_web.pdf

Дополнительная методическая опора:
IAEA, Generic Procedures for Assessment and Response during a Radiological Emergency / gamma-spectrometry procedures:
https://www-pub.iaea.org/MTCD/Publications/PDF/te_1092_web.pdf
