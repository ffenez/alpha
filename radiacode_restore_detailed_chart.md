# Исправление отображения графика мощности дозы

## Что видно на скриншотах

Старый вариант при окне **5 мин** и `n ≈ 295` показывает подробный
временной ряд с большим количеством последовательных колебаний.

Новый вариант при практически том же объёме данных (`n ≈ 296`) визуально
превращает ряд примерно в 10--12 крупных узлов и добавляет широкие
полосы вокруг линии.

Значит, судя по интерфейсу, исходные данные в окне есть, но presentation
layer слишком сильно агрегирует их перед отрисовкой.

## Что вернуть по умолчанию

Для **Мощность дозы → 5 мин** вернуть старое подробное представление:

-   максимально доступное временное разрешение;
-   X = реальный timestamp измерения;
-   подробная линия, а не \~10 временных buckets;
-   последнее измерение у правого края `сейчас`;
-   реальные пропуски не соединять;
-   live-обновление при поступлении новых данных;
-   не использовать широкие percentile/envelope-полосы как основной вид
    короткого live-графика.

Пятиминутный режим должен прежде всего показывать реальную динамику
измерений.

## Нужен ли нынешний сглаженный вариант

Да. Он полезен как **дополнительный аналитический режим**, особенно на
длинных интервалах, где сотни или тысячи точек становятся визуальным
шумом.

Но он не должен заменять подробный режим на 5 мин.

## Добавить

Снизу кнопкой рядом с другими лог подробнее.

### Детально

-   raw samples либо shape-preserving downsampling только при реальной
    необходимости;
-   сохранять локальные пики и провалы;
-   не делать грубую bucket-агрегацию короткого окна.

### Сглаженно

Можно использовать текущую агрегацию: - временные bins; - центральную
оценку; - диапазон вокруг неё.

Но в коде должно быть однозначно определено, что именно означают
внутренняя и внешняя заливки. Не рисовать статистические полосы без
определённой семантики.

## Важное архитектурное требование

Два режима должны быть только двумя способами визуализации **одних и тех
же измерений**.

Не создавать отдельные наборы данных.

Pipeline:

`raw samples -> time window -> presentation transform -> renderer`

Где:

`Detailed -> raw / shape-preserving decimation`

`Smoothed -> statistically defined aggregation`

Статистика `P10 / median / P90 / n` должна рассчитываться по данным
выбранного временного окна и не меняться от переключения визуального
режима.

## Длинные интервалы

Для больших диапазонов downsampling допустим и нужен для
производительности, но он должен сохранять форму и экстремумы ряда.

Не использовать простое прореживание вида «каждая N-я точка».

## Интерактивный масштаб

Режим `Детально / Сглаженно` не заменяет навигацию по времени.

На полноэкранном графике: - pinch по X меняет временной масштаб; -
горизонтальный pan перемещает окно в историю; - `сейчас` возвращает к
live-edge; - на live-edge новые точки двигают окно; - после ручного
ухода в историю viewport не должен самостоятельно возвращаться к
`сейчас`.

## Что найти в коде

Найти точку, где текущий pipeline превращает `n ≈ 296` исходных
измерений в небольшое число визуальных точек.

Проверить: 1. источник измерений; 2. repository / Flow; 3. формирование
временного окна; 4. bucketization; 5. downsampling; 6. chart state; 7.
renderer.

Не исправлять проблему просто увеличением количества buckets. Нужно
разделить подробное отображение и статистическую агрегацию.

## Acceptance criteria

Для `5 мин`, режим `Детально`:

1.  При `n ≈ 300` видна подробная структура ряда, аналогичная старому
    варианту.
2.  Новые измерения появляются непрерывно.
3.  Последняя точка находится у правой границы `сейчас`.
4.  Настоящие gaps не соединяются линией.
5.  `P10 / median / P90 / n` не зависят от режима визуализации.
6.  `Детально ↔ Сглаженно` меняет только представление.
7.  Возврат в `Детально` восстанавливает подробный ряд.
8.  Длинные интервалы остаются производительными благодаря
    shape-preserving downsampling.

## Не менять

Без отдельной причины не трогать: - расчёт мощности дозы; - накопленную
дозу; - пороги L1; - расчёт P10/median/P90; - хранение исходных
измерений; - уже работающую live-логику.

Это исправление presentation layer и стратегии агрегации графика, а не
физики измерения.
