# RadiaCode — Spectrum UI Compact V3

## Цель

Сделать экран **Спектр** рабочим инструментом, а не длинной технической страницей.

Условие:
- `Пояснения на экранах = ВЫКЛ`;
- показывать только данные, которые помогают понять текущий спектр или выполнить действие;
- методические и справочные тексты убирать из основного потока;
- подробности оставлять по запросу.

## Что сейчас перегружает экран

Сейчас экран перегружен четырьмя вещами: большой таблицей пиков с длинными inline-комментариями, слишком подробным блоком спектральных диапазонов, отдельной большой карточкой «Дополнительный анализ» и тяжёлым меню `...` с тремя огромными кнопками.

При выключенных пояснениях это всё должно стать существенно компактнее.

## Новая структура экрана

Оставить только 4 уровня:

1. состояние спектра;
2. сам график;
3. значимые пики / кандидаты;
4. действия.

Всё остальное — по запросу.

## Верхняя панель

Сейчас:

```text
Δt 191:56:02 · 17 003 655 имп
[Спектр] [- фон] [Лин] [Степень] [Лог] [i]
```

Предлагаю:

```text
Спектр                         ⋮
Дом · 191 ч 56 мин · 17,0 млн имп
```

Ниже:

```text
[Лог] [Фон]
```

`сглаж.` оставить маленькой кнопкой внутри графика.

Убрать из постоянного UI:
- `Лин`;
- `Степень`;
- отдельную `i`.

Масштаб Y перенести в:

```text
⋮ → Масштаб Y
    Линейный
    Степенной
    Логарифмический
```

Справку:

```text
⋮ → Справка по спектру
```

## Профиль спектра

Профиль должен быть виден прямо в summary.

Примеры:

```text
Дом · 191 ч 56 мин · 17,0 млн имп
```

или:

```text
Без профиля · 191 ч 56 мин · 17,0 млн имп
```

если это фон:

```text
Дом · фоновый · 191 ч 56 мин
```

Это важнее, чем постоянные controls `Лин / Степень / Лог`.

## График

График оставить главным визуальным объектом.

Не уменьшать его ради служебной информации.

Пример:

```text
┌──────────────────────────────┐
│                              │
│          spectrum            │
│                              │
│                        сглаж.│
└──────────────────────────────┘
```

## Пики — сократить таблицу

Сейчас:

```text
E, кэВ | ПЛОЩАДЬ | ЗНАЧИМОСТЬ | ВОЗМОЖНОЕ СОВПАДЕНИЕ
```

В compact mode:

```text
ПИКИ

86,8 кэВ      179,6σ
572,1 кэВ      18,4σ
920,7 кэВ      15,3σ
1100,0 кэВ     23,0σ
1440,5 кэВ     94,4σ      K-40
```

Оставить:
- энергию;
- значимость;
- кандидат, если есть.

Убрать из основной таблицы:
- площадь;
- длинные комментарии;
- rejected-candidate explanations.

Площадь и остальное показывать по тапу по строке.

## Не показывать rejected candidates inline

Сейчас есть строки:

```text
Tl-208: противоречит ожидаемым линиям
Bi-214: противоречит ожидаемым линиям
```

Они ломают плотность таблицы.

В основном списке:

```text
572,1 кэВ   18,4σ   —
920,7 кэВ   15,3σ   —
1100,0 кэВ  23,0σ   —
1440,5 кэВ  94,4σ   K-40
```

По тапу:

```text
Кандидат Tl-208 отклонён:
ожидаемые дополнительные линии не подтверждены.
```

## Тап по пику

```text

площадь      21 719
```

## Спектральные диапазоны

Collapsed:

```text
СПЕКТРАЛЬНЫЕ ДИАПАЗОНЫ        >
3 диапазона
```

Expanded:

```text
100–300        12,78 с⁻¹      52 %
300–700         2,09 с⁻¹       8 %
700–1500        0,78 с⁻¹       3 %

Отношение        16,36
```

В compact mode убрать:
- `± σ`;
- число импульсов;
- `покрыто каналами`;
- фактические границы каналов;
- объяснение про центр канала;
- длинные методические комментарии.

Всё это перенести в отдельный technical sheet.

## Технические данные

Отдельный экран / bottom sheet:

```text
Технические данные

100–300 кэВ
12,78 ± 0,0043 с⁻¹
8 829 225 импульсов
фактические границы 99,8–299,1 кэВ

...

Спектральное отношение
16,36 ± 0,023
```

Это expert data, а не основной экран.

## Спектральное отношение

В compact:

```text
Отношение    16,36
```

Если эта величина не используется пользователем напрямую, вообще не показывать её в collapsed summary.

## Дополнительный анализ

Сейчас большая карточка:

```text

A/B сравнение >
Спектрограмма >
Радон >
Линия во времени >
```

Убрать её из основного вертикального потока.

Оставить одну строку:

```text
АНАЛИЗ                         >
```

По тапу открывать bottom sheet:

```text

```

Основной экран спектра не должен быть launcher-меню всех функций приложения.

## Нижние действия

Сейчас:

```text
[Сохранить в историю] [Сделать фоном] [...]
```

Предлагаю одну primary action только если она реально нужна.

Если текущий спектр не сохранён:

```text
[ Создать снимок ]
```

Рядом `⋮`.

Если snapshots/autosave уже делают сохранение автоматически — primary кнопку убрать полностью.

`Сохранить в историю` заменить на более точное действие `Создать снимок спектра`.

## Новый overflow `⋮`

Нативный action sheet:

```text
Спектр

Создать снимок
Сделать фоновым

Экспортировать
Импортировать

Масштаб Y
Настройки отображения
Технические данные
Справка

────────────
Сбросить накопление
```

`Сбросить накопление`:
- destructive;
- в самом низу;
- с подтверждением.

## Сброс накопления

Не показывать первой кнопкой.

Confirm:

```text
Сбросить накопленный спектр?

Текущий накопленный спектр будет очищен.

[Отмена] [Сбросить]
```

Claude должен проверить реальное поведение кода перед формулировкой текста про сохранённые снимки.

## Импорт / экспорт

В overflow:

```text
Импортировать спектр
Экспортировать >
```

Export submenu:

```text
N42
XML
CSV
HTML-отчёт
```

Показывать только реально поддерживаемые форматы.

## При `Пояснения на экранах = OFF` убрать конкретно

Убрать из рабочего потока:

```text
импульсов: 8 829 225 · покрыто каналами: ...
```

```text
Канал целиком относится к окну, если его центр попал внутрь...
```

```text
Tl-208: противоречит ожидаемым линиям
```

```text
Bi-214: противоречит ожидаемым линиям
```

Также убрать:
- `i` рядом со спектральным отношением;
- кнопки `подробности`, если они открывают только explanatory text;
- серые методические подписи;
- статистические оговорки.

## Что оставить всегда

Не скрывать:
- энергию;
- значимость;
- candidate nuclide;
- статус `кандидат`;
- время накопления;
- профиль;
- статус фонового спектра;
- ошибки;
- предупреждения о невалидных данных;
- короткую критическую научную оговорку, если без неё UI становится вводящим в заблуждение.

## Визуальная плотность

Уменьшить vertical spacing:
- между графиком и пиками;
- между peaks и spectral bands;
- между spectral bands и analysis.

Не использовать большую отдельную card для каждого раздела.

Главный визуальный вес должен быть у графика.

## Правило дальнейшего дизайна Spectrum screen

Перед добавлением любого нового элемента Claude должен проверить:

```text
Нужен ли он:
1. чтобы понять текущий спектр;
2. чтобы выполнить частое действие;
3. чтобы увидеть ошибку/риск?
```

Если нет — элемент идёт в:
- Details;
- Help;
- Overflow;
- отдельный analysis screen.

## Acceptance criteria

Готово, когда:
- при выключенных пояснениях нет длинных серых текстов;
- график доминирует;
- профиль виден;
- `Лин / Степень / Лог` не занимают большую постоянную панель;
- peaks читаются за несколько секунд;
- площадь скрыта из compact table;
- rejected candidates не создают длинные inline-строки;
- spectral bands помещаются в 4–5 компактных строк;
- technical counts/σ/channel coverage вынесены в details;
- «Дополнительный анализ» не занимает большую карточку;
- reset не является первым действием;
- import/export находятся в overflow;
- основной экран выглядит как измерительный инструмент, а не научная документация.
