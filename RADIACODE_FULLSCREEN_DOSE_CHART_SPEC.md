# ТЗ: полноэкранный график мощности дозы

## Цель

Доработать полноэкранный график так, чтобы короткие окна сохраняли живую
динамику RadiaCode, а длинные --- корректную статистическую агрегацию.
Пользователь выбирает только временное окно; способ представления
выбирается автоматически.

## 1. Масштабы

-   **15м:** максимально детальные сохранённые данные, без
    искусственного сглаживания.
-   **1ч:** высокая детализация; минимальная агрегация только при
    необходимости.
-   **6ч:** Q50 по временным корзинам + Q25--Q75 + Q10--Q90.
-   **24ч/7д:** предагрегированные данные и квантили; значимые короткие
    эпизоды сохраняются отдельными маркерами.
-   Не добавлять пользователю переключатели raw/median/aggregation.

## 2. Неполное окно

Если выбрано `6ч`, но накоплено только 47 минут: - предпочтительно
показывать фактически доступный диапазон и `данных: 47 мин из 6 ч`; -
либо сохранять абсолютное окно, но явно маркировать пустую область
`нет данных`. Никогда не интерполировать BLE/disconnect gaps и не
продолжать последнюю точку через пропуск.

## 3. Адаптивная Y-ось

Не заставлять текущие значения около 0,14--0,18 мкЗв/ч занимать малую
часть экрана только потому, что L1 = 0,30. - Масштабировать область
робастно по распределению текущего окна с разумным padding и минимальным
span. - Если L1 вне диапазона --- закреплённый индикатор `↑ L1 0,30`. -
Если L1 внутри диапазона --- обычная красная пунктирная линия. - Один
экстремум не должен бесконтрольно расширять шкалу.

## 4. Конверты

Для агрегированных корзин: - линия: Q50 (медиана); - внутренняя полоса:
Q25--Q75; - внешняя: Q10--Q90.

Не использовать `mean ± SD` вокруг медианы. Не использовать min--max как
основную заливку. Квантильные полосы --- наблюдаемый разброс, **не
погрешность прибора**.

## 5. Короткие всплески

Downsampling не должен скрывать важные короткие эпизоды. Для корзин
сохранять min/max, время extrema и event flags. Значимый экстремум
показывать отдельным `▲`/event marker.

Тап показывает время, длительность, max, медиану корзины, P90 и
связанное событие. Экстремум не расширяет квантильный конверт
искусственно.

## 6. Гистограмма

Сохранить распределение текущего окна, но сделать блок сворачиваемым.
Основные показатели: P10, медиана, P90, N. Для bins использовать
обоснованное правило (например Freedman--Diaconis) с ограничением
количества bins и защитой от малого N.

## 7. Статистика

Компактно: `P10 · медиана · P90 · N · окно`

В `Расширенная статистика`: P10, P25, Q50, P75, P90, min, max, MAD, SD
(`наблюдаемый разброс`), N, фактическое покрытие, gaps, размер корзины,
точный/приближённый метод квантилей и параметры approximation.

## 8. Объяснение

На основном экране: \> Линия --- медиана интервала. Полосы показывают
наблюдаемый разброс значений, а не погрешность прибора.

KLL, rank error, алгоритм агрегации и прочие технические сведения убрать
в `Как построен график` / расширенную статистику.

## 9. Курсор

Tap/drag включает курсор. Показывать: - время/интервал; - медиану; -
Q25--Q75; - Q10--Q90; - N; - max; - событие; - отношение к baseline
только при зрелом baseline.

Не писать `×4,8 к привычному`. Писать конкретно: `×4,8 к P90 профиля`.

## 10. Zoom и навигация

-   drag: история;
-   pinch: временной zoom;
-   double tap: оптимальный масштаб;
-   `сейчас`: правый край.

Разрешение агрегации меняется автоматически. Zoom может менять
детализацию, но не научный вывод из одних и тех же исходных данных.

## 11. Четыре разные сущности

UI обязан различать: 1. измеренное прибором значение; 2.
неопределённость измерения; 3. наблюдаемый статистический разброс
временной выборки; 4. исторический baseline конкретного профиля.

Не смешивать их визуально или терминологически.

## 12. Архитектура данных

Предпочтительно:
`raw measurements → minute/hour aggregates → render resolution`

Агрегаты должны сохранять N, покрытие, quantile sketch/квантили,
min/max, время extrema и event flags.

Для длинной истории не перебирать миллионы raw SQLite-строк при каждом
открытии.

### Важно

Квантиль квантилей не равен квантилю исходной выборки. Для длинных окон
использовать mergeable quantile sketch либо другой алгоритм с
документированной ошибкой. Если значение приближённое --- это явно
указывать. Не хардкодить ошибку KLL без привязки к фактической
конфигурации реализации.

## 13. Минимум действий

Пользователь управляет только тем, **что посмотреть**, а не тем, **как
это вычислять**.

Автоматически: - разрешение; - агрегация; - Y-scale; - gaps; -
extrema; - переход live → history; - выбор точных/приближённых
квантилей.

## 14. Не делать

-   не копировать официальный UI буквально;
-   не соединять gaps;
-   не скрывать реальные всплески сглаживанием;
-   не называть Q10--Q90 погрешностью;
-   не использовать min--max как типичный/доверительный диапазон;
-   не центрировать σ-полосу вокруг медианы;
-   не растягивать Y только ради далёкого L1;
-   не выдавать approximation за точное значение;
-   не заставлять пользователя выбирать статистический алгоритм;
-   не делать выводы `норма/безопасно/опасно` только из baseline места.

## 15. Проверки

Проверить: 1. стабильный фон; 2. короткий контролируемый подъём; 3.
длительный подъём; 4. единичный выброс; 5. BLE disconnect/reconnect; 6.
малый N; 7. неполное покрытие; 8. 15м → 1ч → 6ч → 24ч → 7д; 9. pinch
zoom; 10. сохранение события после агрегации; 11. независимость научного
вывода от zoom; 12. L1 внутри и вне Y-range; 13. отсутствие интерполяции
gaps; 14. short-window квантили против raw ground truth; 15. long-window
approximation против raw ground truth.

## Критерий готовности

Тап по карточке открывает полноэкранный график. Пользователь выбирает
временной диапазон и при необходимости zoom; всё остальное приложение
делает автоматически. Короткие события остаются обнаружимыми, gaps
честно видны, статистика не создаёт ложной точности, а метод вычисления
доступен по запросу.
