# RadiaCode Settings V2 — современная нативная система настроек

## Цель

Пересобрать настройки как часть современного Android-приложения: компактно, нативно, без административного ощущения и без инженерных текстов на первом уровне. Главный экран должен показывать **что можно изменить + текущее состояние**, а формулы, тонкости и редкие параметры — только по запросу.

Текущие скриншоты уже визуально аккуратные, но системно мешают: слишком крупная кнопка «Назад», повтор названия страницы справа, много крупных карточек, много пустоты, смешение toggle/segmented/text `Вкл/Выкл`, длинные объяснения, debug-параметры среди обычных настроек и слишком много техничности.

---

# 1. Общая структура

Сделать 4 смысловых блока и 6–7 строк максимум на первом экране:

```text
Настройки

ИЗМЕРЕНИЕ
Тревоги                         Обычный        >
Профили и фон                   Дом · авто     >

ПРИЛОЖЕНИЕ
Отклик                          Клики          >
Интерфейс                       Система · 105% >

ПРИБОР
RadiaCode 110                   подключён · 84% >

СИСТЕМА
Данные и диагностика                           >
О приложении                    0.6.5          >
```

Переименовать:
- `Вид` → `Интерфейс`;
- `Уведомления и отклик` → `Отклик`;
- `Прибор` на главном уровне → имя конкретного подключённого прибора;
- debug/архивы убрать из `О приложении`.

---

# 2. Навигация

На вложенных страницах использовать обычный compact TopAppBar:

```text
←  Тревоги
```

Удалить текущую схему:

```text
[← Назад]                      [Тревоги]
```

Правый чип с названием страницы ничего не добавляет. Большая кнопка `Назад` съедает много полезной высоты.

Нижнюю навигацию приложения оставить на корневом Settings, но **скрывать на вложенных настройках**, чтобы `Тревоги`, `Профили`, `Интерфейс` ощущались как одна hierarchy, а не как отдельные top-level разделы.

На планшете/landscape использовать list-detail: список категорий слева, detail справа.

---

# 3. Единый язык компонентов

Ввести reusable preference-компоненты:

```kotlin
SettingRow()
SwitchSettingRow()
ValueSettingRow()
SliderSettingRow()
ChoiceSettingSheet()
SettingsSection()
```

Правила:
- бинарное состояние → настоящий `Switch`;
- 2–4 частых взаимоисключающих варианта → segmented/button group;
- редкий выбор → строка `Название  Значение >` + bottom sheet;
- числовой диапазон → `Slider`;
- сложный набор параметров → отдельный экран;
- action → обычная строка/кнопка, но только если это действительно действие.

Не использовать текстовые псевдопереключатели `Вкл/Выкл`, если это обычный boolean.

---

# 4. Карточки

Сейчас карточка используется почти для любой группы, из-за чего экран выглядит растянутым.

Сделать:
- одна surface-карточка на логическую группу, а не на каждую настройку;
- внутри — ListItem/rows с небольшим вертикальным шагом;
- divider только там, где реально разделяет смысл;
- меньше радиус, меньше вертикальные padding;
- одинарная настройка не обязана жить в большой рамке.

Цель: нативная плотность Android Settings, но сохранить вашу светлую научную эстетику.

# 5. Тревоги

## Проблема сейчас

Экран одновременно показывает `сейчас`, `обычно здесь`, `L1` и длинные формулы каждого режима. Это скорее справка, чем настройка.

## V2

```text
Тревоги

Режим
[Обычный] [Чувствительный] [Свой]

Порог сейчас                 0,30 мкЗв/ч
или 2× обычного уровня профиля

Как это работает? >
```

Переименовать:
- `Обычная` → `Обычный`;
- `Высокая` → `Чувствительный` (иначе кажется, что речь о высокой тревоге).

Краткое описание выбранного режима:

```text
Обычный
Меньше ложных тревог · подтверждение 2 мин
```

или:

```text
Чувствительный
Раньше замечает небольшие изменения · подтверждение 1 мин
```

Формулы и P90 убрать под `Подробнее`.

### Свои пороги

При выборе `Свой` — отдельный экран:

```text
L1                         0,30 мкЗв/ч >
Относительный критерий     2× P90      >
Подтверждение              2 мин       >
Возврат                    Авто        >
Повтор тревоги             ...        >
```

# 6. Профили и фон

Это один из ключевых экранов и его стоит сделать понятнее.

## Список профилей

Убрать `+` справа от каждой строки: он воспринимается как «создать ещё», а не открыть профиль.

```text
⌂ Дом                         активен   >
  0,14–0,16 мкЗв/ч · 4,1 ч данных

→ В пути                                >
  обычный фон не обучается

○ Без места                             >
  обычный фон не обучается

+ Новый профиль
```

Шаблоны:

```text
Офис   Дача   Родители
```

Без `+` внутри каждого chip.

## Экран профиля

```text
Дом

Обычный фон
0,14–0,16 мкЗв/ч
4,1 ч пригодных наблюдений
● модель готова

Автовыбор профиля                    [switch]
Wi‑Fi                                Home_5G >
Местоположение                       Не используется >

Обновлять обычный фон                [switch]
Новые стабильные измерения уточняют модель места.

Спектральный профиль                 Собирается >
```

### `Заморозить обучение`

Убрать этот технический термин.

Вместо:

```text
Обновлять обычный фон                [switch ON]
```

OFF означает: модель сохранена, новые данные её не меняют.

### Уход из знакомой Wi‑Fi

Вместо большого абзаца:

```text
Смена профиля после потери Wi‑Fi     3 мин >
```

Bottom sheet:

```text
Сразу
1 мин
2 мин
3 мин
5 мин
10 мин
```

Короткий subtitle:

```text
Не переключает профиль при кратком пропадании сети.
```

### Хранение измерений

`Хранение сырых измерений` заменить на:

```text
История измерений                    Без ограничения >
Занято: 184 МБ
```

В sheet:

```text
Без ограничения
1 год
90 дней
30 дней
```

Термин `сырые` оставить только в диагностике.

# 7. Отклик

Разделить `Поиск` и `Тревога`.

## Поиск

```text
Сигнал при поиске
[Нет] [Клики] [Тон] [Вибро]
```

Это хороший случай inline single-choice, потому что режим меняют быстро.

`Тон по энергии` показывать **только если выбран Тон**:

```text
Высота тона зависит от энергии       [switch]
Более энергичные импульсы звучат выше.
```

При `Нет/Клики/Вибро` строку скрывать, а не disabled.

## Тревога

```text
Звук и вибрация тревоги              >
```

Внутри:

```text
Звук тревоги                         [switch]
Мелодия                              Системная >
Вибрация                             [switch]
Повтор                               Пока уровень высокий >
```

# 8. Интерфейс

Текущий экран перегружен, поэтому сгруппировать: `Язык`, `Стиль`, `Тема`, `Масштаб`, `Единицы`, `Цвета`, `Главная`.

## Язык

Редкий выбор — не нужен постоянный segmented control.

```text
Язык                                 Русский >
```

Bottom sheet:

```text
Системный
Русский
English
```

## Стиль

`Оформление: Научный терминал / 8-bit` переименовать:

```text
Стиль                                Научный >
```

В sheet дать небольшие previews двух вариантов.

## Тема

Это частый понятный выбор, можно оставить inline:

```text
Тема
[Система] [Тёмная] [Светлая]
```

## Масштаб

Кастомные массивные слайдеры заменить обычными Material sliders:

```text
Размер текста                         105 %
────────────●────

Размер интерфейса                     105 %
────────────●────
```

Кнопку `Сбросить масштаб` показывать **только когда хотя бы одно значение ≠ 100%**.

Не держать большую кнопку `Вернуть 100 %` постоянно.

## Единицы

Вместо большого radio-list:

```text
Единицы дозы                          мкЗв/ч >
```

Bottom sheet:

```text
мкЗв/ч
мкР/ч
```

# 9. Пояснения и цвета

## Пояснения на экранах

```text
Пояснения на экранах                  [switch]
Показывать короткие подсказки рядом со сложными показателями.
```

## Цвет главного числа

`Цвет числа по фону места` заменить на:

```text
Подсвечивать отклонения цветом        [switch]
Главное значение меняет цвет при заметном отличии от обычного уровня места.
```

## `Багровый при`

Слишком техническое название.

```text
Красный уровень                       2× обычного >
```

Показывать только если цветовое выделение включено.

Предпочтительнее вообще связать с тревогой:

```text
Красный уровень                       Как L1 >
```

а ручной override оставить advanced-опцией. Иначе визуальный красный и тревога могут иметь разные критерии.

## Цвет следа

Переименовать так, чтобы было ясно, что это карта:

```text
Цвет маршрута                         Относительно места >
```

Выбор:

```text
Относительно фона места
Относительно диапазона маршрута
Свои пороги
```

# 10. Настройка Главной

Текущие стрелки ↑/↓ и слово `видна` выглядят как внутренний configurator.

Сделать отдельный экран:

```text
Главная

Быстрые разделы
≡ Поиск                            [switch]
≡ Спектр                           [switch]
≡ Карта                            [switch]
≡ История                          [switch]

Показатели
Тренд за час                       [switch]
Доза сегодня                       [switch]

Графики
Скорость счёта                     [switch]
Жёсткость                          [switch]
```

Reorder через drag handle `≡`, не стрелками.

`Главная — всегда видна` удалить: если её нельзя скрыть, это не настройка.

Хорошо добавить live mini-preview результата настройки.

# 11. Прибор

Верх страницы — compact status block:

```text
RadiaCode 110
● подключён

84 % батарея    25 °C
поток 1 Гц
```

Disconnected:

```text
○ не подключён
```

## После перезагрузки

Вместо большого абзаца:

```text
Возобновлять после перезагрузки        [switch]
Автоматически подключаться к последнему прибору и продолжать запись.
```

## Сигналы прибора

Сейчас UI рисует binary control, хотя состояние неизвестно. Это вводит в заблуждение.

Если протокол не позволяет readback:

```text
Звук прибора                       Неизвестно >
Вибрация прибора                   Неизвестно >
```

Tap:

```text
Приложение не может прочитать текущее состояние.

[Выключить]
[Включить]
```

После команды можно писать `Последняя команда: включить`, но не выдавать её за реально прочитанное состояние.

Если readback появится — тогда настоящий switch.

# 12. Частота записи / спектрограмма в фоне

Текущий блок слишком инженерный.

Если параметр относится именно к спектру, назвать:

```text
Спектрограмма в фоне                   Обычно >
```

В sheet:

```text
Подробно
каждые 5 с · выше расход батареи

Обычно
каждые 30 с · рекомендуется

Экономно
каждые 10 мин · большие интервалы
```

Тексты про `≈1,32 МБ/сутки`, слияние старше 7 дней и алгоритм агрегации убрать с пользовательского уровня.

Перенести в `Данные и диагностика → Хранилище → Подробнее`.

Вместо постоянного поля на `О приложении`:

```text

```

Экран:

```text

Не будет включено:
• координаты маршрутов
```

# 18. Контекстные настройки

Dependent settings лучше скрывать, а не серить.

Примеры:
- `Высота тона зависит от энергии` показывать только при `Тон`;
- `Красный уровень` — только когда включено цветовое выделение;
- profile background controls — только для профилей, которые обучают фон;
- настройки прибора — показывать с честным состоянием подключения.

Если настройка недоступна по существенной причине и её важно видеть — оставить строку с понятным subtitle.

---

# 19. Сохранение

Большинство настроек применять сразу:
- тема;
- язык;
- режим тревоги;
- звук;
- retention;
- единицы;
- scale.

Кнопка `Сохранить` нужна только для:
- связанного набора custom thresholds;
- сложной конфигурации спектральных диапазонов;
- destructive actions;
- форм, где несколько полей должны измениться атомарно.

---

# 20. Состояния settings

Каждая настройка, зависящая от прибора/БД, должна иметь явную модель:

```text
Loading
Loaded
Unavailable
Unknown
Error
Stale
```

Нельзя заменять `Unknown` на `Off`.
Нельзя молча показывать старое значение как текущее.

---

# 21. Motion

Использовать спокойную нативную Material motion:
- dependent row → `AnimatedVisibility`;
- choices → ModalBottomSheet;
- switch/slider → стандартная Material animation;
- reorder → лёгкий elevation во время drag;
- никакого bounce/игровой motion;
- смена темы и scale — мягко, без лишней театральности.

---

# 22. Поиск в настройках

Когда настроек станет больше — добавить search icon в AppBar.

Примеры синонимов:

```text
звук
→ Сигнал при поиске
→ Звук тревоги
→ Звук прибора
```

```text
фон
→ Профили и фон
→ Обновлять обычный фон
→ Спектральный профиль
```

---

# 23. Хранение настроек

Не держать настройки разрозненными mutable state.

Логически разделить repository:

```text
AppPreferences
DevicePreferences
ProfilePreferences
DiagnosticPreferences
```

Глобальная настройка не должна случайно менять конкретный профиль и наоборот.
Для пользовательских preferences использовать DataStore/typed repository и Flow/ViewModel state.

---

# 24. Что оставить визуально

Оставить:
- светлый спокойный фон;
- teal accent;
- моноширинные цифры там, где отображаются измерения;
- uppercase section labels;
- минималистичные chips для быстрого выбора;
- общую визуальную идентичность приложения.

Не копировать Android Settings один-в-один. Нужен **нативный interaction model + ваш научный visual language**.

---

# 25. Что удалить

Удалить без сожаления:
- огромные `← Назад`;
- правый chip с названием текущего экрана;
- повтор заголовков;
- текстовые `Вкл/Выкл` вместо Switch;
- `+` справа у каждого профиля;
- стрелки ↑/↓ для reorder;
- `Главная — всегда видна`;
- длинные инженерные абзацы на первом уровне;
- постоянно видимую кнопку `Вернуть 100 %`;
- debug archive из `О приложении`;
- `сырые измерения` в обычном UI;
- `Заморозить обучение`;
- `Высокая` как название чувствительности тревоги;
- binary toggle, если состояние прибора неизвестно.

# 29. Acceptance criteria

Settings V2 готовы, если:
- корневой экран содержит не больше 6–7 строк;
- title страницы не повторяется;
- detail screen не выглядит как ещё один top-level раздел;
- boolean использует Switch;
- частый single-choice использует segmented/button group;
- редкий choice открывается bottom sheet;
- на первом уровне нет технических абзацев длиннее ~2 строк;
- текущее значение видно до входа в настройку;
- Unknown честно называется Unknown;
- dependent settings появляются контекстно;
- простые настройки применяются сразу;
- profile/global/device settings разделены;
- debug не находится в `О приложении`;
- reorder делается drag-and-drop;
- expanded width использует list-detail;
- каждый основной пункт понятен без чтения справки.

# 30. Правило для всех будущих настроек

Перед добавлением любого нового пункта ответить:

```text
1. Это действительно решение пользователя?
2. Нужно ли видеть его регулярно?
3. Можно ли выбрать разумное автоматическое значение?
4. Нужно ли объяснение прямо здесь или достаточно «Подробнее»?
```

Если параметр можно безопасно вычислить автоматически — не делать настройку.
Если параметр нужен только диагностике — не класть его в обычные Settings.
Если настройка требует абзаца объяснения — сначала улучшить её название и interaction design.

**Настройки должны становиться короче по мере того, как приложение становится умнее.**
