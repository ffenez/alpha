# 001. Kotlin + Compose, собственный порт протокола cdump/radiacode (MIT), Kable для BLE, MapLibre для карты

Дата: 2026-08-09. Статус: accepted; решение о карте отменено ADR 003 (MapLibre → osmdroid, 2026-08-10)

## Контекст

Нужно современное, лёгкое и безопасное Android-приложение для дозиметра-спектрометра RadiaCode 110 (BLE): живые показания, спектр, журнал, карта с автоматическими метками повышенного фона. Целевое устройство — Pixel с GrapheneOS без Google Play Services. Разобраны изнутри три работающие реализации протокола и одно Android-приложение:

- **cdump/radiacode** (Python, MIT, активно поддерживается) — канонический реверс-инжиниринг: BLE GATT сервис `e63215e5-7003-49d8-96b0-b024798fb901` (write `…e6`, notify `…e7`), кадрирование «uint32 LE длина + payload» поверх нотификаций, запись чанками по 18 байт, строго один запрос в полёте с матчингом по эхо 4-байтового заголовка. Команды: SET_EXCHANGE 0x0007 (init `01 ff 12 ff`), SET_TIME 0x0A04, RD/WR_VIRT_SFR 0x0824/5, RD_VIRT_STRING 0x0826 и др. VS: DATA_BUF 0x100 (real-time поток), SPECTRUM 0x200, ENERGY_CALIB 0x202, SPEC_ACCUM 0x205 (канонично; 0x201 из radiacode.js — ошибка), SPEC_DIFF 0x206. Спектр: 1024 канала, E(keV)=a0+a1·ch+a2·ch², формат v1 — RLE+дельта (4-битный код кодирования на ран). Прошивка ≥ 4.8 обязательна; известный баг — лишний хвостовой 0x00 в VS-ответах.
- **mkgeiger/RadiaCode** (C++/ESP32, MIT) — тот же протокол на «настоящем» GATT-центральном устройстве: 5 мс пауза между чанками записи, таймаут ответа 30 с для больших спектров.
- **darkmatter2222/Open-RadiaCode-Android** (Kotlin, **без лицензии — код неприкосновенен**, протокол сам портирован из cdump) — полевое доказательство жизнеспособности: 1 Гц опрос DATA_BUF + посекундный дифференциальный спектр по BLE работает; грабли: 500 мс пауза после включения CCCD, 25 с таймаут SET_EXCHANGE, фиктивное поле длительности у SPEC_DIFF. Антипаттерны: SharedPreferences вместо БД, broadcast-шина, монолитные активности, ноль тестов, захардкоженный домашний сервер по HTTP.

Полевой опыт: устройство держит только одного BLE-клиента (сосуществование с официальным приложением невозможно); пейринга нет (запрос пароля = сломанное состояние); главный источник разрывов — энергоменеджмент Android, лечится foreground service + исключение из battery optimization. Открытые неоднозначности для спайка на устройстве: единицы dose_rate в RealTimeData (cdump #56), дрейф base_time/ts_offset (#63).

## Решение

- **Kotlin + Jetpack Compose (Material 3)**, minSdk 26, coroutines/Flow, без DI-фреймворка (ручная композиция — приложение маленькое).
- **Протокол — собственный чистый Kotlin-порт cdump/radiacode (MIT, с атрибуцией)**: кадрирование, VS/VSFR, RLE-декодер спектра, DATA_BUF-декодер. Константы и структуры сверяются с cdump как первоисточником.
- **BLE — Kable (JuulLabs, Apache-2.0)**: coroutines-first обёртка над GATT (состояния соединения, нотификации как Flow, MTU). Поверх неё — наш последовательный request/response-слой. Если спайк покажет проблемы — откат на сырой GATT по проверенному рецепту (18-байтовые чанки, ожидание ack каждой записи).
- **Хранение — Room (SQLite)**: временные ряды измерений, треки, снимки спектров.
- **Карта — MapLibre GL Native (BSD-2) + векторные тайлы OpenFreeMap** (без ключей и аккаунтов, анонимно, агрессивный кэш). Геолокация — стандартный `LocationManager` (без Fused/GMS).
- **Foreground service** типа connectedDevice+location для непрерывного измерения и записи трека.
- Бюджет задержки (P0): показания на дашборде обновляются с частотой опроса DATA_BUF 1 Гц, отрисовка кадра < 16 мс; полный спектр — < 3 с при negotiated MTU.

## Альтернативы

- Официальное приложение — закрытое, требует аккаунтов/GMS-привычек, цель проекта — его заменить.
- Переиспользовать Open-RadiaCode-Android — нет лицензии; архитектурно непригодно (см. выше).
- Flutter/React Native — лишний runtime для BLE-интенсивного приложения, Compose легче и нативнее.
- osmdroid (Apache-2.0, проверен в прior art) — работает, но растровые тайлы выглядят устаревшими; остаётся запасным вариантом при проблемах с MapLibre. **Запасной вариант сработал: MapLibre дал серый экран на целевом устройстве дважды, карта переведена на osmdroid (ADR 003).**
- RxAndroidBle / Nordic BLE — зрелые, но тянут Rx/Java-стиль; Kable даёт тот же контроль в идиоматичных корутинах.

## Последствия

- Полный контроль над протоколом и нулевая зависимость от GMS; вся логика тестируема JVM-юнит-тестами (декодеры — на зафиксированных байтовых дампах).
- Порт протокола — наша ответственность: изменения прошивок отслеживать по upstream cdump.
- MapLibre добавляет ~5 МБ к APK; приемлемо. Стоимость выхода из Kable/MapLibre низкая — оба за интерфейсами.
- Спайк (этап 1 роадмапа) обязателен до строительства UI вокруг BLE: критерий убийства — нестабильность соединения >1 разрыва за 10 минут при исключении из battery optimization.
