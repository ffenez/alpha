# ADR 006. Движок спектральных доказательств вместо единого score

Статус: принято (2026-08-12); подключён к экрану Спектра (2026-08-13) как
ЕДИНСТВЕННЫЙ источник вердиктов о кандидатах — мост
`ui/logic/PeakEvidence.kt` (`PeakEvidenceBridge`) наполняет и колонку
«возможное совпадение», и справку нуклида одним результатом
(`AlgorithmVersions.PEAK_EVIDENCE` v1). `IsotopeMatcher` и `LineConsistency`
помечены `@Deprecated`, с экрана сняты, живут для тестов и чтения старых
результатов (`isotope_match` v1 не бампался — его математика не менялась).
Контекст: требование проектной научной спецификации — подсказка нуклида
остаётся гипотезой, а не находкой (документ рабочий, в репозиторий не входит),
ADR 005 (описательный вывод без сводного балла).

## Проблема

Действующий `IsotopeMatcher` отвечает на вопрос **«какая известная линия
оказалась рядом?»**. У этого вопроса два неустранимых дефекта:

1. **Ответ улучшается от расширения библиотеки, а точность падает.** Чем плотнее
   сетка линий, тем чаще произвольный пик во что-нибудь «попадает». Поэтому
   расширять библиотеку до 30–50 нуклидов ДО появления дискриминации — значит
   ухудшать precision и называть это прогрессом.
2. **Отсутствие линии не участвует в выводе.** Спектр, где виден только 1764 кэВ
   без гораздо более яркого 609 кэВ, физически не может быть Bi-214, но матчер
   об этом не знает: он не смотрит на то, чего нет.

Нужен движок, который отвечает на другой вопрос: **какой целостный decay
signature согласуется со всеми наблюдаемыми И отсутствующими признаками с
учётом разрешения прибора.**

## Решение: каскад доказательств, а не взвешенная сумма

Реализовано в `app/src/main/kotlin/app/alpha/analysis/evidence/` (чистый
JVM, без единой пользовательской строки).

```
ObservedPeak ──► ArtifactInterpreter ──► кандидаты по всем линиям нуклида
                                          ├─ LineObservabilityRule (что обязано было быть видно)
                                          ├─ ResolutionAmbiguities (что прибор не различает)
                                          ├─ IntensityConsistencyEvaluator (отношения площадей)
                                          └─ CalibrationDiagnostics (остатки ΔE — общие на спектр)
                                                   ▼
                                            NuclideEvidence(classification)
```

### Почему не единый score

Схема вида `score = 0.4·энергия + 0.3·число линий + 0.2·интенсивность +
0.1·период` выглядит научно, но коэффициенты берутся из воздуха: их нечем
откалибровать и нечем проверить. Хуже того, единственное число скрывает, какое
именно доказательство сработало, и делает вывод непроверяемым для человека.

Вместо этого движок возвращает СТРУКТУРУ: сколько линий совпало, какие
ожидались видимыми и не нашлись, какие альтернативы прибор физически не
различает, сходятся ли отношения площадей, что с калибровкой. Класс
(`WEAK / SUPPORTED / AMBIGUOUS / CONTRADICTED`) — результат правил, каждое из
которых можно прочитать и оспорить отдельно. Процентов уверенности нет.

### Почему не полноценный likelihood

Правильный следующий уровень — пуассоновское правдоподобие по каналам,
`μᵢ = фонᵢ + Σⱼ Aⱼ·Responseⱼ(Eᵢ)`, то есть сравнение целого ожидаемого
detector response spectrum. Для него нужны четыре вещи, которых у проекта нет:

- матрица отклика детектора,
- измеренная кривая эффективности ε(E),
- модель континуума/рассеяния,
- проверенная энергетическая калибровка.

Ни одну из них нельзя «оценить по литературе» для конкретного кристалла в
конкретном корпусе. Peak-evidence engine — правильный уровень сложности для
CsI(Tl) RC-110 на имеющихся данных; переход к likelihood возможен, когда
появятся измерения, и он НЕ ломает эту архитектуру (модели подключаются через
уже существующие интерфейсы).

### Разделение сущностей

`LibraryLine` (свойство ядра: энергия, выход, provenance, неопределённости) и
`ObservedPeak` (свойство измерения: центроид, его σ, FWHM, нетто-площадь, её σ,
значимость) — разные типы. Смешение этих двух вещей и есть корень вопроса
«какая линия оказалась рядом».

σ центроида выведена как стандартная ошибка среднего по нетто-импульсам:
σ ≈ FWHM/(2,355·√N). Она не включает неопределённость вычитания континуума и
калибровку, поэтому названа оценкой снизу. σ нетто-площади не пересчитывается
приближением √N — она восстанавливается точно из значимости, которую
`PeakDetection` считает по формуле IAEA.

### Provenance: пустая неопределённость ≠ ноль

Все линии библиотеки помечены `DataSource.ENSDF` (IAEA Live Chart / NuDat 3), а
их `energyUncertaintyKeV` и `intensityUncertaintyPercent` равны `null` —
источник, из которого числа пришли в приложение, неопределённостей не дал.
Придумывать их запрещено: σ_ref стоит в знаменателе z-оценки и напрямую
управляет тем, какие совпадения признаются приемлемыми. Неизвестная σ_ref
входит нулём СОЗНАТЕЛЬНО — это делает знаменатель меньше, z больше и критерий
строже. Поле `source` существует, чтобы переход на DDEP/LNHB (evaluated data с
неопределённостями) был заменой данных, а не переписыванием движка.

## Что является инженерным параметром

Параметр — это число, выбранное нами по инженерным соображениям, а не
измеренное на приборе и не взятое из справочника. Каждое такое число названо
инженерным в KDoc рядом с ним:

| Параметр | Значение | Почему именно оно |
|---|---|---|
| `EnergyMatching.CALIBRATION_SIGMA_FRACTION` | 1 % от E | точность заводской калибровки RadiaCode не опубликована; 1 % даёт σ_cal ≈ 6,6 кэВ на 662 кэВ — заметно меньше FWHM (≈ 53 кэВ), то есть параметр не подменяет разрешение |
| `EnergyMatching.CALIBRATION_SIGMA_FLOOR_KEV` | 0,5 кэВ | у 59,5 кэВ один процент дал бы точность лучше ширины канала |
| `EnergyMatching.MAX_ACCEPTABLE_Z` | 3 | соглашение, а не физика; решает только, создавать ли кандидата |
| `ArtifactInterpreter.ESCAPE_MIN_PARENT_KEV` | 1500 кэВ | формальный порог рождения пар 1022 кэВ, но у порога сечение исчезающе мало; 1500 — общепринятая граница заметности escape-пиков |
| `ArtifactInterpreter.BACKSCATTER_MIN_KEV` | 200 кэВ | верхняя граница 255 кэВ физическая (m_e c²/2), нижняя — практическая |
| `LineObservabilityRule.EFFICIENCY_MONOTONE_MIN_KEV` | 150 кэВ | ниже неё ход ε(E) искажает поглощение в корпусе, и односторонний довод неприменим |
| `CalibrationDiagnostics.RELIABLE_MIN_SIGNIFICANCE` | 8σ | вдвое строже порога поиска пиков: у слабого пика центроид сам плавает |
| `CalibrationDiagnostics.MIN_RESIDUAL_SIGMA_KEV` | 0,1 кэВ | без пола один яркий пик получил бы почти бесконечный вес |
| `ContextEvidence.IMPLAUSIBLE_HALF_LIVES` | 10 | «практически исчез» (2⁻¹⁰ ≈ 0,1 %) — соглашение, а не граница |

Модель разрешения — ПАРАМЕТР, а не константа: по умолчанию действует
`SqrtResolution` (FWHM = R₆₆₂·√(662·E), R₆₆₂ берётся у конкретной модели
прибора), но интерфейс `ResolutionModel` принимает `MeasuredResolution`
(FWHM = √(a + bE + cE²)) без правок логики. Заявленные вендором 8,4 ± 0,3 %
относятся к линии Cs-137 и на весь диапазон не распространяются.

## Отрицательное доказательство и его граница

Отсутствие линии становится доводом ПРОТИВ кандидата только в состоянии
`EXPECTED_OBSERVABLE`. Ожидаемая площадь считается от найденной линии того же
нуклида: `A_pred = A_ref·(Iγ/Iγ_ref)·(ε(E)/ε(E_ref))`. Отношения эффективностей
у нас нет, поэтому вместо подстановки ε = 1 используется ОДНОСТОРОННИЙ довод:

- эффективность полного поглощения малого сцинтиллятора выше 150 кэВ убывает с
  энергией — качественное свойство, а не наша подгонка;
- для линии НИЖЕ опорной `A_ref·(Iγ/Iγ_ref)` — оценка снизу: превысила предел
  обнаружения Карри (L_D = 2,71 + 4,65·√B) → линия обязана была быть видна;
- для линии ВЫШЕ опорной то же число — оценка сверху: ниже предела → увидеть её
  было нечем;
- иначе `UNDETERMINED`.

Следствие, которое надо знать: **пропавшая линия ВЫШЕ опорной сегодня никогда
не становится противоречием.** Например, отсутствие 1332,5 кэВ при видимом
1173,2 кэВ Co-60 не опровергает Co-60 до появления кривой эффективности. Это
честная цена отсутствия ε(E), а не дефект правил.

## Группы неразрешимости

Две линии считаются неразличимыми, если расстояние между ними меньше ожидаемой
FWHM (аналог критерия Рэлея). Критерий отвечает на вопрос «способен ли ПРИБОР
их развести», а не «совместим ли центроид» — поэтому он сознательно
консервативен. Следствия на текущей библиотеке: 351,9 (Pb-214) неотделима от
364,5 (I-131), 238,6 (Pb-212) от 242,0 (Pb-214), 583,2 (Tl-208) от 609,3
(Bi-214), 510,8 (Tl-208) от аннигиляционной линии 511 кэВ. Кандидат, у которого
ВСЕ совпавшие линии лежат в таких группах, получает `AMBIGUOUS`: движок не
назначает победителя там, где прибор не даёт информации. Классический пример
≈186 кэВ (U-235 / Ra-226) в библиотеке пока отсутствует, механика от этого не
зависит.

## Артефакты интерпретируются ДО нуклидов

511 кэВ (аннигиляция), escape-пики E−511 / E−1022 (только у родителей выше
1500 кэВ), суммы известных совпадающих каскадов (Co-60 1173+1332, Bi-214
609+1120 и 609+1764 по схемам уровней ENSDF) и обратное рассеяние
(E' = E/(1+2E/m_ec²)) — это ОБЪЯСНЕНИЯ-кандидаты. Формулировка принципиальна:
артефакт не «обнаружен», он снимает необходимость вводить ради пика новый
нуклид. Пик при этом продолжает участвовать в сопоставлении: 511 кэВ и линия
Tl-208 510,8 кэВ для RC-110 неразличимы, и подавлять Tl-208 было бы такой же
ошибкой, как объявлять его.

## Калибровка — только диагностика

Остатки ΔE(E) по надёжным совпадениям дают взвешенный сдвиг с собственной σ и
(от трёх точек) наклон. Молчаливой автокоррекции нет и не будет: сдвиг
оценивается по совпадениям, полученным при той же калибровке, и тихая
коррекция замкнула бы петлю, подтвердив любую первоначальную гипотезу.

Важная деталь: в остатке НЕ учитывается σ_cal, хотя в z-оценке она стоит. Здесь
σ_cal — искомая величина, и её присутствие в знаменателе скрывало бы ровно тот
сигнал, который ищется.

Известное ограничение: совпадения ищутся в окне ±3σ_cal, поэтому сдвиг больше
~3 % шкалы не диагностируется — при нём линии просто перестают совпадать.
Отличить «шкала уехала» от «в спектре ничего нет» движок не умеет.

## Контекст отдельно от спектра

Период полураспада НЕ входит в спектральный вывод: это свойство нуклида, а не
измерения. `ContextEvidence` живёт рядом, значение по умолчанию —
`NOT_EVALUATED`, и это не синоним «правдоподобно».

## Потолок осторожности — политика текста

Движок не содержит `HintConfidence` и вообще ни одной пользовательской строки.
Формулировки вида «спектр совместим с…» принадлежат UI. Иначе научную модель
пришлось бы ломать при каждой правке текстовой политики интерфейса.

## Что осталось невыполненным

- **Кривая эффективности ε(E) не измерена.** Пока `DetectorEfficiencyModel` не
  реализован, отношения интенсивностей возвращают `NotEvaluated(NO_EFFICIENCY_MODEL)`
  вместе с сырыми отношениями, а отрицательное доказательство работает только в
  одну сторону (см. выше).
- **Модель разрешения не измерена.** Действует √E-приближение с одной вендорской
  точкой; ниже ~100 кэВ оно занижает ширину, потому что не содержит шума тракта.
- **σ_cal не измерена** — инженерная 1 %.
- **Неопределённости ядерных данных отсутствуют** (ENSDF-выборка). Переход на
  DDEP/LNHB — замена данных, поля уже есть.
- **Библиотека не расширена** — сознательно: сначала дискриминация, потом
  расширение до 30–50 нуклидов.
- ~~Движок не подключён к экрану Спектра~~ — подключён (2026-08-13, см.
  статус). Правила отображения: артефакт подписывается артефактом;
  `CONTRADICTED` — прочерк с пометкой «противоречит ожидаемым линиям» в
  деталях; `AMBIGUOUS` — группа без победителя. Заметное следствие
  консервативного критерия Рэлея на текущей библиотеке: одиночная линия
  661,7 кэВ (Cs-137) попадает в группу с 637,0 кэВ (I-131) — расстояние
  24,7 кэВ меньше FWHM ≈ 52 кэВ, поэтому чистый Cs-137 показывается группой
  «Cs-137 / I-131», а не победителем. Это зафиксировано тестом моста; выход —
  измеренная модель разрешения и/или пересмотр критерия группы, не подмена
  вердикта в UI.

## Что нужно измерить на приборе

1. **Разрешение** — FWHM на нескольких линиях (Am-241 59,5; Cs-137 661,7;
   K-40 1460,8; Tl-208 2614,5), подгонка √(a + bE + cE²) → `MeasuredResolution`.
2. **Относительная эффективность** ε(E) — источники известной активности в
   фиксированной геометрии; достаточно ОТНОСИТЕЛЬНОЙ кривой →
   `DetectorEfficiencyModel`.
3. **Точность энергетической шкалы** — остатки ΔE по тем же линиям: даёт честное
   σ_cal вместо инженерного 1 % и заодно проверяет диагностику калибровки.
4. **Контрольные спектры** для валидации классификации: чистый Cs-137, чистый
   K-40 (калийная соль), торийсодержащий образец (Tl-208 + escape-пики),
   радоновая промывка после дождя (Bi-214/Pb-214).
