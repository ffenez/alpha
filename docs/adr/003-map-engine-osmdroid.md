# 003. Карта — osmdroid (растровые тайлы OSM) вместо MapLibre GL Native

Дата: 2026-08-10. Статус: accepted. Отменяет решение о карте из ADR 001.

## Контекст

ADR 001 выбрал MapLibre GL Native + векторные тайлы OpenFreeMap, а osmdroid
(Apache-2.0) записал запасным вариантом «при проблемах с MapLibre».

Проблемы наступили. На целевом устройстве (Pixel, GrapheneOS) экран «Карта»
показывал серый прямоугольник **дважды**:

1. с пакетом `org.maplibre.gl:android-sdk` (рендер Vulkan);
2. после переключения на `org.maplibre.gl:android-sdk-opengl` 13.4.1 (рендер
   OpenGL) — тот же серый экран.

Диагностика недоступна: на телефоне пользователя нет adb/logcat, а обе
поломки лежат внутри GPU-конвейера чужого движка. Два независимых бэкенда
рендера, один и тот же симптом — это не единичный баг драйвера, а класс
отказа, который мы не можем ни воспроизвести, ни исправить, ни объяснить
пользователю. Продолжать перебор рендер-артефактов вслепую — не инженерия.

## Решение

Карта — **osmdroid 6.1.20 (Apache-2.0)** на растровых тайлах OSM standard
(«Mapnik»).

- У osmdroid нет собственной поверхности рендера: тайлы и оверлеи рисуются
  обычным `Canvas` на штатном hardware-слое окна. Класса отказа «серый экран
  из-за GPU-конвейера движка» у него просто нет.
- Из APK ушёл весь нативный код (MapLibre ≈12 МБ на ABI), вместе с ним —
  ограничение сборки одним arm64-v8a.
- Политика тайлов OSM Foundation обязывает: **отличительный User-Agent**
  (ставим имя пакета; библиотечное значение по умолчанию «osmdroid» на
  серверах OSM заблокировано) и никакого bulk-скачивания — поэтому офлайн
  предзагрузка района сознательно не реализована, есть только обычный кэш
  просмотренного (512 МБ в cache-каталоге приложения).
- Тёмная тема: цветовая матрица «инверсия + поворот тона на 180°» вместо
  готового `TilesOverlay.INVERT_COLORS`. Голая инверсия переводит каждый
  оттенок в дополнительный (лес становится пурпурным, вода — оранжевой);
  поворот тона возвращает оттенки при инвертированной светлоте. Сверху лёгкое
  обесцвечивание и затемнение, чтобы подложка не спорила с янтарной рампой
  трека. Светлая тема — без фильтра.
- Приватность (инвариант CLAUDE.md) не меняется: запрос тайла несёт только
  координаты тайла и User-Agent, ключей и аккаунтов нет, телеметрии в
  библиотеке нет.

## Альтернативы

- **Продолжить с MapLibre**, подбирая рендер/версии — отклонено: два бэкенда
  уже дали один симптом, а инструментов диагностики на устройстве нет.
- **Google Maps SDK** — исключён инвариантом: целевое устройство без GMS.
- **Свой тайловый вьюер** — решённая инженерная задача (кэш, зум, проекция,
  жесты); писать заново без причины запрещено правилами проекта.

## Последствия

- Растровая карта выглядит проще векторной и не имеет плавного зума между
  уровнями. Это цена за карту, которая гарантированно рисуется.
- Метки трека рисует один батч-оверлей (2000 кругов за кадр), а не 2000
  `Marker`-объектов; попадание тапа считается по пикселям последнего кадра
  чистой функцией `TrackMap.nearestIndex` — логика тестируется на JVM.
- Экран «Карта» показывает честный статус тайлов («загружаются / готово /
  ошибка сети») и называет причину, если не пришло ни одного тайла — включая
  подсказку про разрешение «Сеть» в GrapheneOS. Полевые отчёты больше не
  сводятся к «просто серый экран».
- Стоимость обратного перехода низкая: движок целиком за `ui/map/`, вся
  математика карты — в `ui/logic/TrackMap.kt`.
