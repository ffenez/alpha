## Разрывы (что делать)

### Этап 1 (спец §3, §4, §21) — СДЕЛАНО
1. **[x] Профили вместо «мест»**: сущность `profiles` (имя, иконка, вложенность «Дом / Спальня», архив, `autoActivate`, `baselineLearning`, `role`), Room v5→v6 переносит места в профили с сохранением id (привязка `samples`/`measurement_sessions` не рвётся). Колонки `placeId` СОЗНАТЕЛЬНО сохранили имя — `ALTER TABLE … RENAME COLUMN` есть только с SQLite 3.25 (API 30), а перестройка таблицы `samples` на телефоне это миллионы строк ради косметики; отображение имени делает сущность (`@ColumnInfo(name = "placeId") val profileId`).
2. **[x] Авто-контекст по Wi-Fi**: чистая state machine `context/ContextMachine` (`AUTO_KNOWN / AUTO_UNCERTAIN(grace) / AUTO_TRANSIT / NO_CONTEXT / MANUAL`), приоритет ручного выбора + «Вернуться к авто», grace 1/2/3/5 мин (по умолчанию 3). GPS не используется.
   *Развилка закрыта*: сеть опознаётся по локальному хешу адреса шлюза/DHCP из `LinkProperties` (`context/NetworkIdentity`) — разрешение на геолокацию не нужно. SSID читается ТОЛЬКО как подпись и только если разрешение уже выдано ради карты. Ограничение честно записано в KDoc: одинаковый шлюз (`192.168.1.1`) у разных сетей даёт одинаковый токен, поэтому привязка — подтверждаемая пользователем подсказка, а не доказательство места.
3. **[x] Baseline admission pipeline**: `baseline/BaselineAdmission` — 7 условий §4.2 по порядку, первое невыполненное = причина; `samples.baselineExcluded` (nullable, ключи стабильны на диске), сырые данные пишутся всегда; карантин 30 мин от КОНЦА эпизода отклонения (`QuarantineWindow`); Поиск = эксперимент через `FastPollHub` → `ServiceStatus.experiment`; ручная заморозка в Настройках.
4. **[x] Расширение статистик baseline**: P25/P75, взвешенный MAD = median(|xᵢ − медиана|) без коэффициента 1.4826 (он предполагает нормальность), длительность валидных измерений, число сырых выборок и число минутных корзин (честное n порядковых статистик).

Отложено сознательно: строгий критерий «статистика измерения пригодна» через режим dead-time/pile-up (§5) — нужны замеры на RC-110; сейчас условие 6 отбраковывает только заведомо неинформативные выборки (не-конечные/отрицательные значения, нулевой счёт, относительная погрешность >50 %).

### Этап 2 (спец §6, §7, §8, §9, §16) — СДЕЛАНО
5. **[x] Энергетические окна**: чистый `analysis/EnergyWindows` — C = Σ Nᵢ по каналам, чей ЦЕНТР попал в [E₁,E₂) (дробить край нельзя: дробный счёт перестаёт быть пуассоновским, как и в `SpectrumMerge`; реально покрытый диапазон возвращается отдельно), R = C/t, σ_R = √C/t, доля окна в спектре; индекс R_low/R_high = C_low/C_high (общее t сокращается) с σ = index·√(1/C_low + 1/C_high). Границы редактируются, лежат в DataStore и уезжают в отчёт; UI повторяет, что индекс — описание состава спектра, а не мера опасности, и что окна — параметр анализа.
6. **[x] Dose projection**: `analysis/DoseProjection` — Ḋ̄ = D_окна / t_измерений, проекция = Ḋ̄ · t_горизонта (год = 8766 ч). На карточке дозы в Истории с переключателем 7/30 дней, формулировкой «если средняя измеренная внешняя фотонная мощность дозы останется такой же — за год ≈ X», меткой «расчёт» и честным перечислением того, что НЕ входит. Меньше часа реальных измерений — проекции нет вовсе.
7. **[x] A/B эксперимент**: `experiments` + `experiment_runs` (Room v6→v7), управляемый экран (вход — чип «A/B ▸» на Спектре): сценарий → геометрия один раз → прогон A → прогон B с показом той же геометрии → сравнение. Математика — `analysis/AbAnalysis` + `analysis/AbExperiment`: net = G − B·(t_G/t_B), σ_net = √(G + B·(t_G/t_B)²) [R4] с выводом в KDoc; статистика пуассоновская — при счёте < 25 в прогоне отношение правдоподобия (девианс 2[G·ln(G/Ĝ)+B·ln(B/B̂)]), иначе χ²-подобный z = нетто/σ; обе считаются всегда, использованная названа в результате. Сравниваются мощность дозы (вспомогательно — секундные показания коррелированы), полный счёт, энергетические окна и полный спектр (девианс/χ² по каналам → Wilson–Hilferty, односторонний). Вердикты только `consistent / changed / strong evidence of change`, «% похожести» запрещён тестом. Спектр прогона — разность снимков начала и конца (`SpectrumCompare.extractInterval`), хранится как `origin='derived'` и не попадает ни в Историю, ни в радоновый тренд. Старт прогона поднимает `ServiceStatus.experiment` (тот же флаг, что у Поиска, теперь с несколькими источниками) — интервал исключается из обучения фона. Расстояние: серия с 1/r² ТОЛЬКО с предупреждением о геометрии, рассеянии и фоне; экранирование: без универсальных коэффициентов ослабления.

### Блок P2 математической спецификации графика («статистика») — СДЕЛАНО, кроме полевой валидации

Источник: `CLAUDE_radiacode_graph_spec.md` §42 (P2), раскрытие — §14, §23, §35–§39, §41.
Подробная техническая записка: `docs/analysis/trend-and-anomaly.md`.

- **[x] Theil–Sen тренд** (§23) — `ui/logic/TrendFit`: β̂ = медиана попарных наклонов по медианам присутствующих корзин, мкЗв/ч на час; OLS остался research-функцией. Тренд не показывается при <12 корзин или размахе <10 мин (оба порога инженерные), выше 250 точек — детерминированное прореживание. Значимость и доверительный интервал НЕ выводятся: поток автокоррелирован.
- **[x] FD-гистограмма + кламп/fallback** (§14) — `ui/logic/DoseHistogram`: h = 2·IQR·n^(−1/3), кламп [8, 40] (продуктовая эвристика), округление границ; fallback'и для IQR = 0 (правило √n), малого N (честное «недостаточно данных для распределения» вместо картинки) и вырожденного распределения (одна корзина). Ось Y подписана тем, что считает: «секунд измерений (1 Гц)».
- **[x] Формальный тест — построен, но НЕ выводится** (§35, §36). В UI только описательные утверждения `analysis/DescriptiveDeviation` (медиана сместилась / разброс шире / вне P10–P90 профиля / короткий всплеск, каждое с числами для «Почему?»). Кандидат теста `analysis/AnomalyStatistics` (Mann–Whitney U + Kolmogorov–Smirnov с поправкой N_eff = N/τ на автокорреляцию) закрыт opt-in аннотацией `@ExperimentalRadiationStatistics`.
- **[x] Валидация ложных срабатываний — харнесс** (§36.5–36.7, §37A) — `analysis/validation/`: сканирование стационарного ряда меряет FP-rate и тревоги/сутки, ряды со ступенькой — power и задержку. На детерминированной синтетике: без поправки 21 % тревог (~154/сутки), с поправкой 0 из 328 при τ̄ = 9,1; ступенька ×1,5 ловится 12/12 за 300 с.

Осталось (полевое, этап P3): реальные записи RC-110 — ≥24 ч стационарного фона и ≥10 повторов контролируемой ступеньки, формат CSV и критерии продвижения описаны в `docs/analysis/trend-and-anomaly.md`. До этого весь `AnomalyStatistics` остаётся экспериментальным.

### Этап 3 (спец §10, §11)
8. **Peak analytics**: centroid, net area, FWHM, resolution, uncertainty; локальная модель пик+континуум; не предполагать идеальную гауссовость везде.
9. **Значимость**: «xσ» только там, где статистика действительно в единицах σ.

### Этап 4 (спец §13, §14)
10. **Radiation fingerprint профиля** (нормированный baseline-спектр) и состояние **«Доза в норме · Спектр изменился»**; fingerprint — вторичный guard обучения baseline.
11. **Change-point detection** с выбранной и валидированной моделью; событие хранит pre/event/post.

### Этап 5 (спец §12)
12. **Multi-line кандидаты** с учётом остатка по энергии, неопределённости калибровки, интерференций и доступности линий; **calibration health** (диагностика дрейфа шкалы).

### Этап 6 (спец §15)
13. **MDA / пределы обнаружения** (Currie, ISO 11929) и объяснимая оценка «сколько ещё измерять» строго относительно поставленной статистической цели.

### Сквозные требования (все этапы)
- **§2 Четыре уровня достоверности** — MEASURED / CALCULATED / STATISTICALLY DETECTED / INTERPRETATION: ввести маркировку в UI и не смешивать уровни в одной фразе.
- **§17 «Почему?»** на главном экране — раскрытие данных, приведших к выводу (диапазон baseline, CPS, наличие спектральной аномалии, длительность baseline, исключённые интервалы).
- **§20 История как научный журнал** — `baselineIncluded` + причина исключения, поздняя правка профиля сессии.
- **[x] §22 Воспроизводимость** — единый источник версий `analysis/AlgorithmVersions` (числа запинены тестом: смена математики обязана прийти вместе с осознанным бампом). Производный снимок хранит `spectra.analysisMeta` (плоский JSON: метод, версии алгоритмов, нормализация, метод фона, источники) — компаратор, объединение и прогоны A/B; эксперимент хранит `algorithmVersion` + `params` (окна, порог переключения статистики, пороги вердикта) и никогда их не переписывает. Экспорт: RC-XML кладёт метаданные в `SampleInfo/Note`, N42 — в `<Remark>` перед всем остальным, отчёт эксперимента — отдельным текстовым файлом.
- **[x] §24 Scientific release gate** (для функций этапа 2) — у `EnergyWindows`, `DoseProjection`, `AbAnalysis` в KDoc блок из 9 пунктов (формула, допущения, единицы, источник, данные валидации, ограничения, тесты, версия алгоритма, что это значит для пользователя). Экран A/B помечен «экспериментальная функция» и в UI, и в отчёте — на реальных данных RC-110 статистика ещё не валидирована. Для функций этапов 3–6 — по мере реализации.

## Порядок

Этап 1 → сквозные §2/§20/§22 → этап 2 → 3 → 4 → 5 → 6. Внутри каждого — сперва чистая математика с тестами (JVM), затем UI.

Сделано: этап 1, сквозные §2/§17/§20/§22, этап 2. Дальше — этап 3 (peak analytics: centroid, net area, FWHM, resolution, uncertainty).

Ждёт проверки на приборе (этап 2): совпадают ли доли энергетических окон с ожиданиями на реальном фоне; работает ли захват спектра прогона (разность снимков) при 5-с опросе и коротких прогонах; согласуются ли вердикты A/B на заведомо одинаковых прогонах (два фона подряд должны давать `consistent` — это и есть проверка порогов на реальном шуме).
