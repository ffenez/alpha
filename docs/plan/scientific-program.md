## Разрывы (что делать)

### Этап 1 (спец §3, §4, §21) — СДЕЛАНО
1. **[x] Профили вместо «мест»**: сущность `profiles` (имя, иконка, вложенность «Дом / Спальня», архив, `autoActivate`, `baselineLearning`, `role`), Room v5→v6 переносит места в профили с сохранением id (привязка `samples`/`measurement_sessions` не рвётся). Колонки `placeId` СОЗНАТЕЛЬНО сохранили имя — `ALTER TABLE … RENAME COLUMN` есть только с SQLite 3.25 (API 30), а перестройка таблицы `samples` на телефоне это миллионы строк ради косметики; отображение имени делает сущность (`@ColumnInfo(name = "placeId") val profileId`).
2. **[x] Авто-контекст по Wi-Fi**: чистая state machine `context/ContextMachine` (`AUTO_KNOWN / AUTO_UNCERTAIN(grace) / AUTO_TRANSIT / NO_CONTEXT / MANUAL`), приоритет ручного выбора + «Вернуться к авто», grace 1/2/3/5 мин (по умолчанию 3). GPS не используется.
   *Развилка закрыта*: сеть опознаётся по локальному хешу адреса шлюза/DHCP из `LinkProperties` (`context/NetworkIdentity`) — разрешение на геолокацию не нужно. SSID читается ТОЛЬКО как подпись и только если разрешение уже выдано ради карты. Ограничение честно записано в KDoc: одинаковый шлюз (`192.168.1.1`) у разных сетей даёт одинаковый токен, поэтому привязка — подтверждаемая пользователем подсказка, а не доказательство места.
3. **[x] Baseline admission pipeline**: `baseline/BaselineAdmission` — 7 условий §4.2 по порядку, первое невыполненное = причина; `samples.baselineExcluded` (nullable, ключи стабильны на диске), сырые данные пишутся всегда; карантин 30 мин от КОНЦА эпизода отклонения (`QuarantineWindow`); Поиск = эксперимент через `FastPollHub` → `ServiceStatus.experiment`; ручная заморозка в Настройках.
4. **[x] Расширение статистик baseline**: P25/P75, взвешенный MAD = median(|xᵢ − медиана|) без коэффициента 1.4826 (он предполагает нормальность), длительность валидных измерений, число сырых выборок и число минутных корзин (честное n порядковых статистик).

Отложено сознательно: строгий критерий «статистика измерения пригодна» через режим dead-time/pile-up (§5) — нужны замеры на RC-110; сейчас условие 6 отбраковывает только заведомо неинформативные выборки (не-конечные/отрицательные значения, нулевой счёт, относительная погрешность >50 %).

### Этап 2 (спец §6, §7, §8, §9, §16)
5. **Энергетические окна** 100–300 / 300–700 / 700–1500 кэВ как параметр анализа + спектральный индекс R_low/R_high (описательный, не мера опасности).
6. **Dose projection** только как экстраполяция с явной формулировкой условия.
7. **A/B эксперимент** (Фон vs Объект, Место vs Место): протокол с фиксацией геометрии и длительностей, net = G − B·(t_G/t_B) с неопределённостью по IAEA [R4], вердикты `consistent / changed / strong evidence of change` (запрет «% похожести»).

### Этап 3 (спец §10, §11)
8. **Peak analytics**: centroid, net area, FWHM, resolution, uncertainty; локальная модель пик+континуум; не предполагать идеальную гауссовость везде.
9. **Значимость**: «xσ» только там, где статистика действительно в единицах σ.

### Этап 4 (спец §13, §14)
10. **Radiation fingerprint профиля** (нормированный baseline-спектр) и состояние **«Доза в норме · Спектр изменился»**; fingerprint — вторичный guard обучения baseline.
11. **Change-point detection** с выбранной и валидированной моделью; событие хранит pre/event/post.

### Этап 5 (спец §12)
12. **Multi-line кандидаты** с учётом остатка по энергии, неопределённости калибровки, интерференций и доступности линий; **calibration health** (диагностика дрейфа шкалы).

### Этап 6 (спец §15)
13. **MDA / пределы обнаружения** (Currie, ISO 11929) и объяснимая оценка «сколько ещё измерять» строго относительно поставленной статистической цели.

### Сквозные требования (все этапы)
- **§2 Четыре уровня достоверности** — MEASURED / CALCULATED / STATISTICALLY DETECTED / INTERPRETATION: ввести маркировку в UI и не смешивать уровни в одной фразе.
- **§17 «Почему?»** на главном экране — раскрытие данных, приведших к выводу (диапазон baseline, CPS, наличие спектральной аномалии, длительность baseline, исключённые интервалы).
- **§20 История как научный журнал** — `baselineIncluded` + причина исключения, поздняя правка профиля сессии.
- **§22 Воспроизводимость** — у каждого производного анализа `algorithmVersion` + параметры; экспорт несёт метод нормализации, метод фона, метаданные калибровки и версии алгоритмов.
- **§24 Scientific release gate** — 9 пунктов на каждую исследовательскую функцию перед переводом в стабильные; до прохождения — помечать как экспериментальную.

## Порядок

Этап 1 → сквозные §2/§20/§22 → этап 2 → 3 → 4 → 5 → 6. Внутри каждого — сперва чистая математика с тестами (JVM), затем UI.
