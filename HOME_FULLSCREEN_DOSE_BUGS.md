# Исправления: Home и полноэкранный график мощности дозы

Claude Code не видит приложенные скриншоты. Ниже --- точное текстовое
описание того, что на них сейчас не так.

## 1. Критическая проблема: Home получает текущие значения, но график считает, что измерений нет

На Home одновременно видно:

-   мощность дозы: `0,14 мкЗв/ч`;
-   скорость счёта: `23,7 ±4,9 с⁻¹`;
-   доза за сегодня: `0,0010 мкЗв`;
-   зелёный индикатор соединения.

То есть приложение получает live-данные от прибора.

Но непосредственно под этим карточка `МОЩНОСТЬ ДОЗЫ` не строит график и
показывает:

`накапливаем измерения...`

Это противоречивое состояние.

### Что проверить

Необходимо проследить один и тот же sample от получения данных до chart
history:

`BLE/device → repository → live state → history/buffer → Home chart`

Особенно проверить, почему значение `doseRate` попадает в главный
показатель `0,14`, но не попадает в series графика.

Не исправлять это таймером, искусственным заполнением или копированием
текущего значения в историю. Нужно найти разрыв в data pipeline.

------------------------------------------------------------------------

## 2. Полноэкранный график подтверждает ту же проблему

После открытия графика мощности дозы fullscreen:

-   сверху показывается `0,15 ±15% мкЗв/ч`;
-   одновременно показывается `прервано 28 с назад`;
-   выбран режим `сейчас`;
-   окно графика = `6 ч`;
-   сам график полностью пуст;
-   по центру написано `В ЭТОМ ОКНЕ НЕТ ИЗМЕРЕНИЙ`.

При этом нижняя статистика показывает:

`P10 0,13 · медиана 0,13 · P90 0,14 · n 34 · 6 ч`

Это логически несовместимые представления одного набора данных.

Если `n = 34` для выбранного 6-часового окна, то в этом же окне
существуют 34 измерения. График не должен утверждать, что измерений нет.

### Вывод

Проблема почти наверняка не только в рисовании линии. Разные части
экрана используют разные: - источники данных; - timestamp; - фильтры
временного окна; - либо преобразования времени.

Нужно установить единый source of truth.

------------------------------------------------------------------------

## 3. Очень вероятна ошибка timestamp/window filtering

Fullscreen имеет ось:

`−6 ч ... −4 ч ... −2 ч ... сейчас`

Статистика видит `n 34`, но renderer не находит ни одной точки внутри
viewport.

Проверить для каждого sample:

-   исходный timestamp;
-   epoch milliseconds vs epoch seconds;
-   monotonic time vs wall-clock time;
-   timezone;
-   преобразование `Instant`;
-   преобразование device timestamp;
-   `now`, используемый для viewport;
-   start/end выбранного окна;
-   условие фильтрации `[windowStart, windowEnd]`.

### Добавить временный debug logging

Для fullscreen 6h вывести:

-   `now`;
-   `windowStart`;
-   `windowEnd`;
-   `series.size`;
-   `filteredSeries.size`;
-   `min(sample.timestamp)`;
-   `max(sample.timestamp)`;
-   `age(lastSample)`;
-   количество samples, используемое для `n`;
-   количество samples, переданное непосредственно renderer.

Эти числа должны сразу показать место расхождения.

------------------------------------------------------------------------

## 4. Нельзя одновременно показывать `n 34` и «нет измерений»

Это отдельный UI invariant.

Если:

`n > 0`

для текущего выбранного окна, состояние:

`В ЭТОМ ОКНЕ НЕТ ИЗМЕРЕНИЙ`

невозможно.

Добавить invariant/test.

### Acceptance

Для одного и того же `window`:

`stats.samples === plotted/eligible samples`

с учётом только явно документированных различий вроде downsampling.

Если статистика рассчитана по другому диапазону, UI обязан это явно
обозначать. Но здесь логичнее использовать один dataset.

------------------------------------------------------------------------

## 5. Статус `прервано 28 с назад` тоже противоречит live-показателю

В fullscreen одновременно:

-   отображается актуальное значение `0,15`;
-   статус говорит `прервано 28 с назад`;
-   Home показывает зелёное соединение.

Нужно разделить минимум три понятия:

1.  **Device connected** --- BLE-соединение активно.
2.  **Latest telemetry received** --- когда пришёл последний пакет.
3.  **Latest sample for this metric** --- когда обновилась конкретно
    doseRate.

Статус графика должен определяться третьим пунктом, а глобальный
connection indicator --- первым.

Если `0,15` получено только что, нельзя писать `прервано 28 с назад`.

Если `0,15` --- старое последнее значение, оно может оставаться на
экране, но должно быть визуально понятно, что оно stale.

------------------------------------------------------------------------

## 6. `прервано` --- плохая формулировка для обычной задержки телеметрии

Для временного отсутствия samples естественнее:

`нет новых данных · 28 с`

или после более длительного периода:

`данные не обновляются · 2 мин`

`прервано` звучит как завершённая сессия/аварийный обрыв и слишком
драматично для краткого gap.

Статус не должен бесконечно считать секунды, если это обычный режим
редкого обновления конкретной метрики.

------------------------------------------------------------------------

## 7. Полноэкранный график визуально сломан в правом верхнем углу

В верхней правой части plotting area накладываются друг на друга:

-   красный `↑ L1 0,30`;
-   текст единицы `мкЗв/ч`.

Текст физически пересекается и становится нечитаемым.

### Исправить

Развести разные overlay layers.

Например:

-   единица --- только в toolbar/header;
-   L1 --- внутри plot с безопасным padding;
-   никакой второй `мкЗв/ч` поверх L1.

Нужен layout collision test для overlay labels.

------------------------------------------------------------------------

## 8. Единица мощности дозы дублируется

В fullscreen она уже есть в верхнем live-value:

`0,15 ±15% мкЗв/ч`

Дополнительная единица внутри правого верхнего угла графика не даёт
полезной информации и создаёт collision с L1.

### Сделать

Убрать единицу из plotting area fullscreen.

Оставить её рядом с live-value/header.

------------------------------------------------------------------------

## 9. Фон fullscreen выглядит как вертикальная «зебра»

На пустом графике особенно хорошо видно большое количество чередующихся
вертикальных серых полос.

Это визуально воспринимается как ошибка рендера, а не как полезная
информация.

Если полосы обозначают gaps/качество/периоды записи, сейчас они: -
слишком контрастные; - слишком многочисленные; - не имеют очевидной
семантики; - перекрывают обычную сетку.

### Требование

Не использовать вертикальные background bands для каждого мелкого gap.

Реальный gap должен прежде всего выражаться отсутствием линии.

Дополнительную заливку применять только для действительно значимого
состояния и делать значительно слабее обычной data layer.

На полностью пустом окне фон должен быть практически чистым: grid +
empty-state.

------------------------------------------------------------------------

## 10. Empty-state должен быть главным содержимым пустого графика

Сейчас надпись:

`В ЭТОМ ОКНЕ НЕТ ИЗМЕРЕНИЙ`

теряется среди: - серых полос; - горизонтальных диапазонов; - сетки; -
L1; - осей.

Если данных действительно нет, график должен упрощаться.

### При `filteredSeries.isEmpty()`

Показывать: - обычные оси; - очень лёгкую grid; - спокойный
empty-state; - без псевдо-data bands, которые выглядят как измерения.

------------------------------------------------------------------------

## 11. Home: `накапливаем измерения...` не должно висеть при уже имеющихся samples

Этот текст допустим только при реальном bootstrap:

`history sample count < minimum required for chart`

Но текущий fullscreen показывает `n 34`, следовательно данные уже
существуют хотя бы в статистическом слое.

Нужно определить единое условие готовности графика.

Например:

-   0 samples → `Нет измерений`;
-   1 sample → показать точку;
-   2+ samples → строить линию;
-   статистические диапазоны появляются только когда выборки достаточно.

Не нужно ждать десятки samples, чтобы вообще показать пользователю
первые данные.

------------------------------------------------------------------------

## 12. Home: профиль `Без места` перегружен техническими сообщениями

Сейчас под главным значением одновременно:

`Ниже порога L1`

`изучаю обычный фон — 0 ч из 3`

`этот профиль не собирает обычный фон`

Последние две строки противоречат друг другу.

Если профиль **не собирает обычный фон**, приложение не должно
одновременно говорить:

`изучаю обычный фон — 0 ч из 3`

### Исправить state machine

Для профиля с background learning disabled показывать только одно
состояние, например:

`Фон для этого профиля не сохраняется`

Но ещё лучше на Home не показывать эту служебную информацию постоянно,
если она не нужна для принятия решения.

------------------------------------------------------------------------

## 13. `Ниже порога L1` --- формально верно, но слабее предыдущего пользовательского статуса

На Home главный вопрос пользователя не «ниже ли L1», а нормальна ли
текущая обстановка.

`Ниже порога L1` --- техническая характеристика alarm threshold.

Если профиль без собственного background baseline, лучше коротко и
честно сообщать именно то, что известно, например:

`Уровень ниже порога тревоги`

Не выдавать это за утверждение «фон нормальный», если baseline для этого
места не собран.

------------------------------------------------------------------------

## 14. `ТРЕНД/Ч — НУЖНО 12` непонятно

Пользователь не понимает, что такое `12`: - секунд? - минут? -
измерений?

Это возвращает старую проблему интерфейса: внутреннее состояние
алгоритма показывается как техническая загадка.

### Исправить

Если нужно 12 минут:

`нужно 12 мин`

Если нужно 12 samples:

лучше не показывать внутреннее число вообще; использовать
`недостаточно данных`.

------------------------------------------------------------------------

## 15. Проверить состояние после открытия fullscreen

Есть риск, что Home и fullscreen подписаны на разные lifecycle
collectors.

Нужно протестировать сценарий:

1.  подключить устройство;
2.  дождаться live doseRate;
3.  убедиться, что Home строит график;
4.  открыть fullscreen;
5.  убедиться, что та же серия видна;
6.  вернуться Home;
7.  свернуть приложение;
8.  открыть;
9.  повторно открыть fullscreen.

Ни один переход не должен: - очищать history; - создавать новый
несинхронизированный buffer; - останавливать collector; - менять
timestamp basis.

------------------------------------------------------------------------

# Архитектурное требование

Не создавать отдельные независимые массивы измерений для:

-   Home chart;
-   fullscreen chart;
-   статистики P10/P50/P90;
-   stale status.

Они должны строиться из одного timestamped time-series source.

Концептуально:

``` text
DoseRateSample(
    timestamp,
    value,
    uncertainty/metadata
)

                 ┌─ Home viewport 1m
Dose history ────┼─ Fullscreen viewport 6h
                 ├─ P10/P50/P90
                 └─ lastSampleAge
```

Различаться должны viewport/downsampling/presentation, а не исходные
данные.

------------------------------------------------------------------------

2.  Почему `n 34`, но renderer получает 0 точек.
3.  Проверить timestamps и фильтрацию 6h window.
4.  Сделать единый dataset для chart/stats/stale.
5.  Проверить lifecycle collectors.

7.  Убрать лишнюю единицу из plotting area.
8.  Исправить чрезмерную вертикальную полосатость.
9.  Сделать корректный empty-state.

## P2

10. Исправить противоречие `изучаю фон` / `профиль не собирает фон`.
11. Заменить непонятное `нужно 12`.
12. Пересмотреть формулировку `прервано`.

# Acceptance criteria

Исправление считается законченным только если:

-   текущее значение doseRate и график получают данные из одной series;
-   если fullscreen показывает `n = 34`, эти измерения действительно
    можно увидеть на графике выбранного окна;
-   при `n > 0` сообщение `В ЭТОМ ОКНЕ НЕТ ИЗМЕРЕНИЙ` невозможно;
-   Home не показывает `накапливаем измерения...`, если доступна
    достаточная history;
-   timestamps корректно попадают в `[now - window, now]`;
-   live/stale status основан на timestamp последнего sample конкретной
    метрики;
-   переход Home ↔ fullscreen не меняет/не очищает данные;
-   background/foreground не ломает обновление;
-   L1 и единицы не перекрываются;
-   пустой график не покрыт вертикальной «зеброй»;
-   UI не показывает одновременно `изучаю фон` и
    `этот профиль не собирает фон`;
-   пользовательские статусы написаны человеческим языком, без
    внутренних чисел алгоритма без единиц.

# Главная проблема одним предложением

**Приложение явно получает текущие измерения и даже умеет вычислить
статистику по 34 samples, но time-series слой графика эти же измерения
не видит или отбрасывает --- сначала нужно исправить единый поток
данных/timestamps, а не косметически чинить график.**
