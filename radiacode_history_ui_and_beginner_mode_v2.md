# RadiaCode — History UI V2 + editing + spectrum profile + beginner explanations

## Цель

Переработать экран **История** так, чтобы он был:
- компактным;
- быстрым для просмотра;
- одинаково понятным для сессий, маршрутов, спектров и исследований;
- без лишних карточек и повторов;
- с полноценным управлением сущностями;
- с корректным отображением профиля;
- совместимым с уже существующей настройкой **«Пояснения на экранах»**.

Главное правило: **История — это рабочий список результатов, а не справочник.**
По умолчанию пользователь должен видеть только то, что нужно для выбора нужной записи.

---

# 1. Что сейчас неудачно

По текущему UI видно несколько системных проблем.

## 1.1. Вкладка «Все» визуально неоднородна

В одном потоке одновременно отображаются:
- исследования;
- маршруты;
- отдельный большой блок спектров;
- сессии.

Но визуально они оформлены по-разному:
- маршруты — отдельными большими карточками с preview;
- спектры — одной большой общей карточкой со списком внутри;
- сессии — списком строк;
- исследование — ещё одной самостоятельной карточкой.

В результате вкладка `Все` выглядит как набор разных экранов, сложенных друг под друга.

### Нужно

Перейти к **единой модели элемента истории**:

```text
[иконка/preview]  Название                     ⋮
                  время · длительность
                  главная метрика · вторичная
```

Различаться должен контент, а не фундаментальный layout.

Базовый компонент:

```text
HistoryItem
```

Структура:

```text
┌──────────────────────────────────────────┐
│ preview │ Дом · идёт                    ⋮ │
│         │ 16 авг 19:37 · 15 ч 49 мин      │
│         │ 0,15 мкЗв/ч · 2,37 мкЗв         │
└──────────────────────────────────────────┘
```

Для разных типов:

### Сессия

```text
Дом · идёт
16 авг 19:37 · 15 ч 49 мин
ср 0,15 мкЗв/ч · доза 2,37 мкЗв
```

### Маршрут

```text
Маршрут · 13:52
15 авг · 2 ч 37 мин · 15 км
ср 0,08 · макс 0,16 мкЗв/ч
```

### Спектр

```text
Спектр
16 авг 20:46 · 175 ч 58 мин
профиль: Дом
```

или, если профиля нет:

```text
Спектр
16 авг 20:46 · 175 ч 58 мин
без профиля
```

### Исследование / продукт

```text
Калий · 100 г
16 авг 21:39 · банка 1 л
данных пока мало
```

# 3. Вкладка «Все»

Сейчас вкладка `Все` перегружена крупными секциями.

Предлагаемая структура:

```text
История                         37 записей

[Все] [Сессии] [Маршруты] [Спектры] [Исследования]

Сегодня
[исследование]
[сессия]
[спектр]

15 августа
[маршрут]
[сессия]

14 августа
[маршрут]
[спектр]
[сессия]
```

То есть:
- единая хронологическая лента;
- группировка по дате;
- без отдельной большой карточки `СПЕКТРЫ` внутри `Все`;
- без больших контейнеров, которые дублируют вкладки сверху.

Это резко улучшит сканирование глазами.

# 4. Вкладки

Сейчас сверху:

```text
Все | Сессии | Маршруты | Спектры
```

Добавить:

```text
Все | Сессии | Маршруты | Спектры | Исследования
```

На узком экране не пытаться втиснуть все пять равной ширины.

Использовать:
- horizontal scrollable tab row;
- либо четыре основных + `Ещё`;
- либо adaptive widths.

Предпочтительно:

```text
ScrollableTabRow
```

с компактными подписями.

# 5. Счётчик «37 сессий» сейчас неверно воспринимается

На экране он остаётся даже когда открыта вкладка `Все`, хотя визуально содержит не только сессии.

Это создаёт двусмысленность.

### Нужно

На `Все`:

```text
37 записей
```

На `Сессии`:

```text
37 сессий
```

На `Маршруты`:

```text
2 маршрута
```

На `Спектры`:

```text
5 спектров
```

На `Исследования`:

```text
1 исследование
```

Если счётчик не даёт пользы — можно вообще убрать из top-level UI и показывать только в фильтре/заголовке.

# 6. Сессии — убрать дублирование ⋮ + >

Сейчас у строки есть одновременно:
- `⋮`;
- `>`.

Они визуально конкурируют и выглядят как два способа открыть одно и то же.

### Правило

- **тап по всей строке** → открыть;
- `⋮` → действия;
- отдельный `>` не нужен.

Это стандартнее и визуально чище.

---

# 7. Сессии — сделать вторичную информацию спокойнее

Сейчас:

```text
ср 0,15 мкЗв/ч   доза 2,37 мкЗв
данных 15 ч 17 мин · пропуски 31 мин
```

Это полезно, но третья строка должна быть context-dependent.

Compact mode:

```text
Дом · идёт
16 авг 19:37 · 15 ч 49 мин
0,15 мкЗв/ч · 2,37 мкЗв
```

Показывать `пропуски 31 мин` только если:
- пропуск достаточно велик;
- влияет на интерпретацию;
- пользователь включил пояснения;
- либо запись открыта детально.

Не заставлять каждую строку объяснять качество данных.

# 8. Пустая сессия

Сейчас:

```text
В пути
16 авг 13:44 · 0 с
измерений в этой сессии не записано
```

Это хорошо как диагностика, но в рабочем списке можно компактнее:

```text
В пути
16 авг 13:44 · 0 с
нет измерений
```

И дать через `⋮`:

```text
Удалить
```

Пустые случайные сессии должны удаляться.

# 9. CRUD: сейчас нельзя менять или удалять исследования

Это функциональный пробел.

Для **исследования/проверки продукта** обязательно добавить:

```text
⋮
Открыть
Переименовать
Изменить описание
Изменить образец / массу / ёмкость / заметку
Экспортировать
Удалить
```

Если часть полей после измерения нельзя менять без нарушения смысла результата, разделить:

```text
Редактируемое:
- название;
- заметка;
- фотография;
- категория.

Неизменяемое после старта:
- исходная геометрия;
- измеренные значения;
- timestamp;
- detector/raw data.
```

Но пользователь **обязан** иметь возможность удалить исследование.

# 10. Удаление исследования

Удаление:

```text
Удалить «Калий · 100 г»?
Будут удалены измерения и сохранённые результаты этого исследования.

[Отмена] [Удалить]
```

Если raw measurements могут быть общими с другой сущностью, не удалять их физически без проверки ownership.

Но пользовательская сущность исследования должна исчезнуть из Истории.

После удаления:

```text
Исследование удалено      [Отменить]
```

если архитектура позволяет безопасный undo.

```text

```

Для маршрута автоматическое имя по умолчанию:

```text

```

Для спектра:

```text

```

Для исследования:

```text

```

Пользователь может заменить на:

```text

```

# 13. Спектры — главная проблема: нет профиля

Сейчас список показывает:

```text
спектр
16 авг 20:46
175 ч 58 мин · фон
```

Но неясно:
- с каким профилем он связан;
- где был снят;
- был ли это `Дом`, `В пути`, `Без места`;
- что означает `фон`.

### Нужно хранить и показывать provenance

Для каждого спектра:

```text
profileId / profileSnapshot
profileNameAtCapture
source
capturedAt
accumulationDuration
deviceId/model
isBackgroundSpectrum
```

# 14. Почему нужен snapshot имени профиля

Нельзя только ссылаться на текущий `profile.name`.

Если пользователь позже переименует:

```text
Дом → Квартира
```

исторический спектр не должен внезапно изменить контекст без следа.

Хранить:

```text
profileId
profileNameAtCapture
```

UI может показывать актуальное имя, но provenance должен быть восстановим.

---

# 15. Как показывать профиль у спектра

Compact:

```text
Спектр
16 авг 20:46 · 175 ч 58 мин
Дом · фон
```

или:

```text
Спектр
16 авг 20:46 · 175 ч 58 мин

```

Если `фон` — отдельный тип spectrum:

```text
Дом · фоновый спектр
```

Если профиля нет:

```text

```

Не оставлять просто `фон`, если пользователь не понимает фон чего именно.

# 17. Меню спектра

`⋮`:

```text
Открыть
Переименовать
Продолжить накопление
Сравнить
Экспортировать >
Изменить профиль...
Удалить
```

### `Изменить профиль`

Разрешать только metadata association, не переписывать исходные измерения.

Если профиль был определён автоматически при capture, показать:

```text
Дом
определён при измерении
```

При ручном исправлении:

```text
Профиль изменён вручную
```

# 26. Семантика текста

Каждый текст в UI классифицировать:

```text
ESSENTIAL
EXPLANATION
HELP
```

## ESSENTIAL

Всегда виден.

Примеры:

```text
данных пока мало
нет измерений
профиль: Дом
прибор отключён
линия не выделяется
совпадение ≠ обнаружение
```

## EXPLANATION

Только если `Пояснения на экранах = ON`.

Примеры:

```text
Измерение пока слишком короткое...
P10–P90 показывает...
Сравнивать можно место с местом...
```

## HELP

Подробная справка.

Shortcut `i` / `Подробнее` можно скрывать в compact mode, но сама справка остаётся доступна централизованно.

Сейчас маршрут — отдельная card, спектры — container card. Это ломает ритм.

# 35. Multi-select


# 39. Меню ⋮ — единая логика

Для всех сущностей порядок действий одинаковый:

```text
Открыть
Переименовать
Экспортировать
Сравнить       [если применимо]
Изменить       [если применимо]
Удалить
```

`Удалить` всегда внизу destructive.

Не делать совершенно разные меню для каждого типа без необходимости.

---

# 40. Naming

Убрать технические названия типа:

```text
Track 2026-08-14...
```

из пользовательского UI.

Автоимена локализуются:

```text
Маршрут · 14 авг 18:51
Спектр · 16 авг 20:46
Исследование · 16 авг 21:39
```

Во внутренней базе UUID остаётся техническим и не показывается.

# 41. Acceptance criteria

Готово, если:

- вкладка `Все` — единая хронологическая лента;
- нет огромной отдельной карточки спектров внутри `Все`;
- сессии, маршруты, спектры и исследования используют общий визуальный язык;
- у spectrum виден профиль / `Без профиля`;
- profile provenance сохраняется при capture;
- исследование можно переименовать;
- исследование можно редактировать в разрешённых полях;
- исследование можно удалить;
- пустые accidental sessions можно удалить;
- маршрут можно удалить;
- spectrum можно удалить;
- тап по item открывает его;
- `⋮` отвечает только за actions;
- лишний `>` убран;
- `37 сессий` заменяется корректным count текущей вкладки;
- `Пояснения на экранах` управляют всеми EXPLANATION/HELP блоками;
- серые длинные пояснения не захламляют рабочий список;
- важные статусы и научные оговорки остаются всегда;
- экран `Проверить продукт` больше не пустая заглушка;
- никакие пользовательские строки не содержат непонятных голых чисел вроде `11` без единицы/контекста.
