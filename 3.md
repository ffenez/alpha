# Fullscreen Chart — сделать график визуально таким же крупным, как в официальном RadiaCode

## Цель

В полноэкранном режиме график должен занимать **максимально возможную часть дисплея** и ощущаться как основной инструмент измерения, а не как один из блоков аналитического экрана.

Ориентир по UX — официальный RadiaCode: после открытия графика почти всё доступное пространство отдаётся области построения, а статистика и управление становятся вторичными.

Не копировать дизайн RadiaCode буквально. Повторить именно **иерархию пространства**.

---

## 1. Главная проблема текущего экрана

Сейчас экран делится примерно так:

* header;
* plot;
* histogram;
* summary statistics;
* expanded statistics;
* time controls;
* log toggle;
* длинное текстовое объяснение.

Из-за этого даже высокий график визуально воспринимается как один из компонентов страницы.

В fullscreen режиме должно быть наоборот:

> **график — экран; остальное — overlay/control layer поверх него или компактная нижняя панель.**

---

## 2. Размер области графика

В portrait fullscreen режиме целевая высота plot area:

```text
≈ 70–80% доступной высоты между system status bar и нижней navigation area
```

Не фиксировать это конкретным количеством dp.

Использовать layout weight / constraints:

```text
header          wrapContent
chart           weight(1f)
bottomControls  wrapContent
```

Главный график должен получать **всё оставшееся пространство**.

Не задавать chart height как жёсткие `400dp`, `500dp`, `60vh` и т. п.

---

## 3. Header сделать компактнее

Текущий верхний блок можно сократить до одной строки:

```text
×   МОЩНОСТЬ ДОЗЫ · 5М           0,16 мкЗв/ч ±15%     [сейчас] [i]
```

Либо две очень компактные строки:

```text
МОЩНОСТЬ ДОЗЫ · 5М
0,16 ±15% мкЗв/ч
```

Не оставлять большой отдельный вертикальный header.

Цель:

```text
header ≤ примерно 8–10% высоты экрана
```

---

## 4. Убрать histogram из постоянной области fullscreen

Histogram сейчас забирает заметную высоту у главного временного графика.

В fullscreen он должен быть:

```text
[Распределение ▾]
```

и по умолчанию свёрнут.

При раскрытии:

* histogram появляется как bottom sheet / collapsible panel;
* основной график может немного уменьшиться;
* после закрытия снова получает максимум площади.

Не держать histogram постоянно открытым.

---

## 5. Статистику сделать компактной нижней строкой

Вместо отдельной большой области:

```text
P10 0,13   MED 0,15   P90 0,17   N 348   5 мин
```

одна компактная строка под графиком.

Расширенные:

* P25/P75;
* MAD;
* SD;
* min/max;
* KLL details;
* coverage;

убрать в:

```text
Расширенная статистика ▾
```

---

## 6. Технический текст убрать с основного fullscreen

Текст:

```text
линия — медиана корзины...
Q25–Q75...
KLL...
```

не должен постоянно занимать место под графиком.

Перенести его в `i`:

```text
[i] Как построен график
```

Это освобождает значительную часть экрана.

---

## 7. Time controls сделать overlay или одной строкой

Сейчас переключатель периода занимает отдельный блок.

Вариант:

```text
[5м] [15м] [1ч] [6ч] [24ч]
```

одной компактной строкой у нижнего края.

Или floating chips поверх нижней части plot area с достаточной прозрачностью.

Не создавать отдельную карточку только под эти кнопки.

---

## 8. Ось X и Y — внутри plot area

Подписи:

```text
12:30   12:32   12:34
0,10    0,20
мкЗв/ч
```

должны быть частью Canvas/Chart, а не дополнительными внешними layout-блоками.

Это позволит графику использовать больше физического пространства.

---

## 9. Full-bleed chart area

Сам chart container должен доходить почти до боковых краёв:

```text
horizontal padding ≈ 8–12dp
```

Не использовать большие card margins как на Home.

Fullscreen — отдельный режим, поэтому ему не нужен тот же уровень внешних отступов, что карточкам главного экрана.

---

## 10. Не помещать график в визуальную карточку

В официальном приложении график ощущается большим ещё и потому, что он не выглядит как card внутри экрана.

В fullscreen:

* без отдельной белой карточки;
* без большого border radius;
* без внешней тени;
* фон экрана = фон plot area.

Graph should feel native to the entire screen.

---

## 11. Bottom sheet для вторичных функций

Всё вторичное:

```text
Распределение
Расширенная статистика
Как построен график
Экспорт
```

открывать снизу как sheet.

Не заставлять пользователя скроллить длинную страницу под графиком.

Это особенно важно: fullscreen graph не должен превращаться в вертикальный analytics page.

---

## 12. Portrait layout

Рекомендуемая структура:

```text
┌────────────────────────────────┐
│ ×  МОЩНОСТЬ ДОЗЫ · 5М    i    │
│    0,16 ±15% мкЗв/ч      сейчас│
├────────────────────────────────┤
│                                │
│                                │
│                                │
│                                │
│          MAIN CHART            │
│                                │
│                                │
│                                │
│                                │
│                                │
├────────────────────────────────┤
│ P10 .13 · MED .15 · P90 .17   │
│ [5м] [15м] [1ч] [6ч] [24ч]   │
│ [Распределение ▾]              │
└────────────────────────────────┘
```

Цель — main chart занимает большую часть экрана.

---

## 13. Landscape

При повороте:

```text
chart = почти весь экран
```

Сверху только тонкая строка:

```text
× · 0,16 мкЗв/ч · P10 .13 · MED .15 · P90 .17 · [5м] [1ч] ...
```

Histogram/statistics открываются overlay.

В landscape график должен занимать около 85–90% полезной площади.

---

## 14. Fullscreen interaction

Чтобы компенсировать скрытую статистику:

* tap → cursor;
* drag → cursor/pan;
* pinch → zoom;
* double tap → reset zoom;
* `сейчас` → вернуть к live edge;
* tap `i` → методология;
* swipe up / `Распределение` → analytics sheet.

Пользователь ничего не теряет — данные просто перестают постоянно занимать пространство.

---

## 15. Главное правило реализации

Не пытаться сделать график больше за счёт увеличения фиксированной высоты.

Нужно изменить **структуру экрана**:

```text
не:
header
chart
histogram
stats
controls
description

а:
compact header
EXPANDING CHART
compact controls
secondary information in sheets
```

То есть `chart` должен быть единственным компонентом с `weight(1f)` / `fillMaxHeight` после compact chrome.

---

## Acceptance criteria

* [ ] plot area занимает не менее ~70% полезной высоты portrait при закрытых дополнительных панелях;
* [ ] histogram по умолчанию не уменьшает график;
* [ ] expanded statistics не занимают постоянное место;
* [ ] техническое описание доступно через `i`, но отсутствует под графиком;
* [ ] временные диапазоны занимают одну компактную строку;
* [ ] chart не находится внутри визуально отдельной card;
* [ ] в landscape plot занимает практически весь экран;
* [ ] все функции предыдущего fullscreen режима остаются доступными без отдельной страницы;
* [ ] никакие статистические алгоритмы не меняются — это только переработка информационной и пространственной иерархии.

## Итог

**Fullscreen должен быть режимом просмотра графика, а не страницей статистики с большим графиком.**

Официальный RadiaCode ощущается крупнее именно по этой причине. Сохранить нашу более строгую математику, но отдать ей UI второго уровня.
