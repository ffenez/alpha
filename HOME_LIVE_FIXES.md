# Home --- исправление live-графиков и состояния данных

## Цель

Исправить поведение главного экрана при работе с подключённым RadiaCode.

Основные проблемы: - Home периодически перестаёт получать/отображать
новые измерения; - после сворачивания и возврата графики снова начинают
обновляться; - появляется бесконечное `нет новых данных · N с`; - график
может соединять точки через реальный пропуск данных; - последняя точка
live-графика не закреплена логично относительно правого края/текущего
времени; - разные элементы Home могут одновременно находиться в
противоречащих состояниях; - на графиках остаётся лишний визуальный и
служебный шум.

Не маскировать проблему принудительным recomposition, периодическим UI
refresh или искусственной интерполяцией. Найти источник рассинхронизации
данных.

------------------------------------------------------------------------

# P0 --- Live data pipeline

Проверить весь путь:

`MeasurementService → repository/store → ViewModel → Compose UI`

Проверить: - `Flow` / `StateFlow`; - subscriptions и collectors; -
`collectAsStateWithLifecycle`; - lifecycle экрана; - отмену coroutine; -
`LaunchedEffect` и keys; - `remember` / `rememberSaveable`; - snapshot
state; - navigation; - background → foreground; - reconnect
устройства; - timestamp последнего реально полученного измерения.

Home должен иметь единый источник истины для live-состояния.

Нельзя создавать независимые freshness-таймеры для отдельных карточек.

------------------------------------------------------------------------

# P0 --- Не соединять пропуски данных

Если между двумя реальными samples существует временной разрыв, линия
графика должна разрываться.

Запрещено: - интерполировать отсутствующие samples; - соединять точки
через настоящий gap; - продолжать последнее значение до `now`; -
генерировать искусственные samples.

Определить `gap threshold` относительно реальной частоты поступления
измерений.

------------------------------------------------------------------------

# P1 --- Настоящий live-chart

Правый край графика должен соответствовать текущему времени.

Последняя свежая точка должна находиться около правого края с небольшим
постоянным визуальным отступом.

При поступлении нового sample: - новая точка появляется справа; - старые
данные движутся влево; - X-axis движется вместе с окном; - сохраняется
заданная длительность окна; - обновление происходит без touch,
navigation или сворачивания приложения.

Не позиционировать последнюю точку исходя только из количества samples.

------------------------------------------------------------------------

# P1 --- Исправить временную ось

Не размещать одиночную метку времени вроде `23:42` произвольно внутри
графика.

Для короткого live-окна можно использовать:

`−1 мин` → `сейчас`

Либо абсолютные timestamps, но их положение должно соответствовать
реальной временной координате.

График CPS визуально ближе к ожидаемой временной модели; при возможности
использовать общую реализацию X-axis для обоих live-графиков.

------------------------------------------------------------------------

# P1 --- Единая freshness model

Все элементы Home должны использовать один timestamp последнего
валидного измерения:

-   мощность дозы;
-   скорость счёта;
-   главный статус;
-   график мощности дозы;
-   график CPS;
-   заключение относительно фона;
-   тренд;
-   статистика.

Не должно существовать ситуации, когда один компонент считает данные
live, а другой stale.

------------------------------------------------------------------------

# P1 --- State machine состояния измерений

Вместо бесконечного `нет новых данных · N с` использовать явные
состояния.

## Live

`Измерение идёт`

Либо не показывать текст, если зелёного индикатора достаточно.

## Stale

`Нет новых данных`

Вторично при необходимости: `последнее измерение 8 с назад`

Не превращать основной статус в бесконечный секундомер.

## Reconnecting

`Восстановление связи…`

## Disconnected

`Прибор отключён`

или

`Связь с прибором потеряна`

------------------------------------------------------------------------

# P1 --- Индикатор состояния

Не показывать одновременно зелёную точку и `Нет новых данных`, если
зелёный воспринимается как нормальная работа измерений.

Состояния: - Live --- зелёный; - Stale/Reconnecting --- оранжевый; -
Disconnected --- серый/красный согласно дизайн-системе.

Если зелёная точка означает только Bluetooth connection, это нужно либо
визуально отделить от freshness, либо изменить семантику индикатора.

------------------------------------------------------------------------

# P1 --- Stale-значение мощности дозы

Старое измерение нельзя визуально выдавать за текущее.

При stale вместо обычного live-представления показывать, например:

`0,15 мкЗв/ч` `последнее измерение`

Можно сохранять приглушённый цвет значения.

------------------------------------------------------------------------

# P1 --- Заключение о фоне

При отсутствии свежих данных не оставлять формулировку:

`Показания обычны для этого места`

как будто это текущий вывод.

Использовать:

`Последние показания были обычными для этого места`

или временно скрывать заключение до восстановления live-потока.

------------------------------------------------------------------------

# P2 --- Текст фоновой статистики

Вместо технического:

`фоновая статистика временно не обновляется`

если причина в отсутствии samples:

`Фон временно не обновляется — нет новых данных`

Текст должен отражать реальную причину состояния.

------------------------------------------------------------------------

# P2 --- Исправить L1

Сейчас `↑ L1 0,30` может пересекаться с Y-axis и другими элементами.

Если L1 находится выше текущего Y-range, показывать компактный указатель
у верхней границы plotting area:

`↑ L1 0,30`

Не рисовать линию порога внутри диапазона, если сам порог находится вне
отображаемого диапазона.

Исключить пересечения L1 с: - Y-axis labels; - grid; - markers; -
другими подписями.

------------------------------------------------------------------------

# P2 --- P10--P90

Историческая полоса P10--P90 не должна восприниматься как норматив
«безопасной радиации».

Это диапазон обычных исторических измерений данного профиля/места.

Для UI использовать короткую человеческую подпись:

`обычный диапазон места`

Подробную статистическую информацию оставить в справке `i`.

------------------------------------------------------------------------

# P2 --- Маркеры событий

На CPS-графике большое количество `△` создаёт шум.

Соседние события агрегировать:

`△ 3`

вместо нескольких почти наложенных друг на друга треугольников.

Подробности можно раскрывать по нажатию.

------------------------------------------------------------------------

# P2 --- Проверить расхождение CPS

Если верхняя карточка показывает, например:

`СЧЁТ 25,1 ±5,0`

а последняя точка CPS-графика:

`25,4`

проверить их семантику.

Если оба значения означают текущий CPS --- использовать один
sample/timestamp.

Если одно усреднённое, а второе мгновенное --- это должно быть явно
определено в модели и UI.

------------------------------------------------------------------------

# P3 --- Убрать лишний текст с графиков

Не возвращать без необходимости: - `5м` около заголовка «Мощность
дозы»; - `30м` около «Скорость счёта»; - дублирующий верхний `мкЗв/ч`; -
диагностический текст вроде `данных: 29 с из 1 мин`.

Карточки должны оставаться визуально простыми.

Единицы измерения показывать только там, где они реально нужны для
понимания шкалы.

------------------------------------------------------------------------

# Regression tests

## Home открыт постоянно

Оставить Home открытым минимум 5 минут.

Ожидается: - графики продолжают обновляться; - новые точки появляются
справа; - временное окно движется; - приложение не требует
взаимодействия пользователя.

## Background → foreground

`Home → свернуть → подождать → открыть`

Ожидается: - поток корректно продолжается; - реальные gaps
сохраняются; - отсутствующие данные не интерполируются; - collectors
корректно восстанавливаются.

## Navigation

`Home → Spectrum → Home`

Ожидается: - live subscription продолжает работать; - график не
зависает; - timestamps корректны.

## Краткий пропуск данных

Ожидается:

`Live → Stale → Live`

График должен содержать настоящий разрыв.

## Disconnect / reconnect

Ожидается:

`Live → Reconnecting/Disconnected → Live`

После восстановления: - stale-индикация исчезает; - новые samples
появляются автоматически; - сворачивать приложение не требуется.

## Длительный разрыв

Ожидается: - последнее значение обозначено как последнее, а не
текущее; - линия заканчивается на timestamp последнего sample; -
пространство до `now` остаётся пустым; - текущий вывод о фоне не
показывается как live; - история не интерполируется.

------------------------------------------------------------------------

# Acceptance criteria

1.  Home может оставаться открытым длительное время и продолжает
    получать новые измерения.
2.  Сворачивание приложения не требуется для оживления графиков.
3.  Последняя свежая точка находится около правого края.
4.  Правый край соответствует текущему времени.
5.  Реальные gaps не соединяются линиями.
6.  После reconnect график автоматически продолжает работу.
7.  Все компоненты используют единый freshness state.
8.  Нет противоречия между индикатором состояния и фактической свежестью
    данных.
9.  Старое измерение не выдаётся за текущее.
10. P10--P90 не выглядит как норматив безопасности.
11. L1 не пересекается с подписями.
12. Маркеры событий не создают стену визуального шума.
13. На графиках нет лишних диагностических подписей.
14. Исправляется первопричина, а не симптомы через forced
    refresh/recomposition.
