# RadiaCode — единый UX открытия объектов и экспорта

## Проблема

Сейчас одинаковое действие в разделе «История» ведёт себя по-разному в зависимости от типа объекта.

### Спектр

При нажатии на спектр сначала открывается modal action sheet:

- Открыть спектр
- Экспорт XML
- Экспорт N42
- Сравнить с другим…
- Продолжить накопление
- Закрыть

То есть первый tap открывает **меню действий**, а не сам объект.

### Сессия

При нажатии на сессию сразу открывается **detail screen** с результатом, статистикой, графиком и кнопкой экспорта.

Это два разных navigation pattern для сущностей одного уровня и одного раздела. Так делать не нужно.

## Единое правило

> Обычный tap по объекту всегда открывает detail screen этого объекта.  
> Действия над объектом находятся внутри detail screen и/или в overflow menu `⋮`.

Никаких промежуточных action modal по обычному tap.

## 1. Спектр

### Было

```text
tap Spectrum
↓
modal
├── Открыть спектр
├── Экспорт XML
├── Экспорт N42
├── Сравнить
├── Продолжить накопление
└── Закрыть
```

### Должно быть

```text
tap Spectrum
↓
SpectrumDetailScreen
```

Верх:

```text
←   Спектр 14.08.2026 19:35                    ⋮
    14 авг 19:35 · накопление 126:47:03
```

На экране сразу:

- график спектра;
- Lin / Power / Log;
- фон;
- сглаживание;
- пики;
- возможные совпадения;
- накопление;
- прибор;
- metadata.

### Overflow `⋮`

```text
Экспортировать
Сравнить с другим спектром
Продолжить накопление
Переименовать
Удалить
```

## 2. Экспорт спектра

Не держать XML и N42 отдельными огромными кнопками на первом уровне.

Tap:

```text
⋮ → Экспортировать
```

или компактная кнопка `Экспорт` в app bar.

Открывается единый export sheet:

```text
Экспорт спектра

Отчёт
HTML
Красивый отчёт для просмотра в браузере

Обмен данными
N42
Стандартный формат спектрометрии

XML
Формат RadiaCode / совместимый XML

Таблица
CSV
Канал · энергия · импульсы
```

## 3. Сессия

Существующий подход сессии правильнее и должен стать эталоном:

```text
tap Session
↓
SessionDetailScreen
```

Но app bar тоже привести к общей схеме:

```text
←   В пути                                     ⋮
    16 авг 19:32 · 4 мин
```

Не использовать одновременно огромную кнопку `← Назад`, отдельную большую кнопку `Экспорт` и отдельный `Профиль >`, если это перегружает верх.

## 4. Действия сессии

Overflow:

```text

```

## 8. Что делать с текущим modal спектра

Удалить его как entry point.

Сейчас он смешивает:

### Navigation
`Открыть спектр`

### Export
`Экспорт XML`
`Экспорт N42`

### Object actions
`Сравнить`
`Продолжить накопление`

Разнести:

```text
tap → открыть
⋮ → действия
Экспортировать → форматы
```

---

## 9. Кнопка «Закрыть»

Огромная отдельная кнопка `Закрыть` в action sheet не нужна.

Sheet закрывается:

- свайпом вниз;
- tap за пределами;
- системным Back.

Если нужен явный cancel — компактное `Отмена`.

---

## 10. Контекстное `⋮` в Истории

Можно оставить `⋮` справа у строки.

Тогда:

```text
tap row → открыть объект
tap ⋮ → быстрые действия
```

Например для Spectrum:

```text
Экспортировать
Сравнить
Продолжить накопление
Удалить
```

Но menu из списка и overflow detail screen должны использовать один action source, чтобы не расходиться.

---

## 11. Long press

Единый secondary pattern:

```text
long press
↓
selection mode
```

Для массовых действий:

```text
Экспорт
Сравнить
Удалить
```

Но long press не должен быть обязательным способом найти обычные действия.

---

## 12. Итоговое правило для Истории

```text
ROW TAP
→ open detail

⋮
→ contextual actions

EXPORT
→ one unified export sheet

LONG PRESS
→ multi-select
```

Это правило применять одинаково к:

- сессиям;
- маршрутам;
- спектрам;
- экспериментам;
- будущим типам записей.

---

## 13. Acceptance criteria

Исправление готово, если:

- tap по Spectrum больше не открывает список действий;
- tap по Spectrum сразу открывает SpectrumDetailScreen;
- tap по Session открывает SessionDetailScreen;
- Route и Experiment работают так же;
- все detail screens используют один navigation pattern;
- `Экспортировать` открывает один reusable export sheet;
- XML/N42 не являются отдельными top-level actions до входа в export;
- огромная кнопка `Закрыть` в spectrum actions удалена;
- `⋮` используется для редких object actions;
- один и тот же action не имеет разных названий на разных сущностях;
- новый тип объекта в Истории обязан следовать тому же контракту.

## Главное решение

Не приводить сессию к modal спектра.

**Привести спектр к модели сессии.**

Сессия уже ведёт себя логичнее: пользователь нажал запись — сразу увидел запись. Именно это должно стать стандартом всей Истории.
